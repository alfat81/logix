# Logix — Брендбук и руководство по эргономике

Версия 1.2 · Утверждён владельцем 24.10.2026 · Обязателен при любых изменениях UI (RULES 2.14)

Источник: утверждённый гайд «Logix — Руководство по эргономике ИИ-агента»
(Version 1.1, передан владельцем в чате 24.10.2026). Как сказано в самом
гайде — «системный промпт для ИИ, работающего над платформой Logix»: все
новые экраны, формы и карточки проектируются строго по этому файлу.

Пункты с пометкой «Дополнение агента» в исходном гайде отсутствуют — это
зафиксированные мной недостающие значения, чтобы документ был применим
без домысливания. Владелец может скорректировать их в любой момент
(список — §8); правится только этот файл.

Дополнение v1.2 (24.10.2026, D24): владелец передал два референс-макета —
публичный лендинг и трёхколоночный «Admin Workspace». Пометка «Макет» —
значения, снятые с этих макетов; «Дополнение агента» — фиксация пробелов
макета, как и раньше. История версий — §10.

### 1.2 Типографика — IBM Plex Sans

Шрифт с открытой апертурой: обеспечивает читаемость мелких цифр и
технических терминов в таблицах.

| Уровень | Начертание | Настройки |
|---|---|---|
| Заголовки | Bold / 700 | tracking-tight |
| Основной текст | Regular / 400 | leading-relaxed |
| Данные (цифры, суммы, номера) | Medium / 500 | tabular-nums — «monospaced-feel»: равная ширина цифр; сам шрифт не моноширинный |

Подключение: `next/font/google` (IBM Plex Sans, веса 400/500/700,
подмножества `latin` + `cyrillic`, `display: swap`), fallback — system-ui.
Шрифт задаётся в `layout.tsx` и привязывается к `--font-sans`.

## 2. Принципы эргономики

1. **Плотность данных.** Компактные таблицы с минимальными отступами,
   но чёткими границами разделов. Важна не пустота, а иерархия.
2. **Версионность документов.** Любое изменение документа визуально
   помечается тегом версии. Переключение между версиями — не более 2 кликов.
3. **Контекстный фокус.** Трёхколоночная вёрстка
   (Навигация | Список | Детали), чтобы пользователь никогда не терял контекст.

## 4. Правила вёрстки окон (Workspace)

Три колонки: **Навигация | Список | Детали** (принцип 3, §2), чтобы
пользователь никогда не терял контекст. Детализация — по
референс-макету владельца «Admin Workspace» (24.10.2026, v1.2).

### 4.1. Навигация (280px, Sand)

- Фиксированная левая панель на Sand, рамка справа Border-Sand.
- Шапка панели: логотип «Logix» (Coral, Bold) + подпись кабинета
  ЗАГЛАВНЫМИ, мелкая, приглушённая («ADMIN WORKSPACE»). (Макет)
- Пункты группируются; заголовки групп — caps, мелкие, приглушённые
  («ОПЕРАЦИИ», «ПАРТНЁРЫ» на макете). Группировка по ролям (Admin,
  Client, Broker) — из исходного гайда; состав и названия разделов
  задаёт информационная архитектура кабинета, не брендбук (§8.8).
- Пункт меню: иконка + подпись. Активный — плашка White (radius-sm),
  иконка и текст Coral, шрифт Medium. (Макет)
- Счётчик у пункта (кол-во активных объектов) — таблетка Coral с белым
  числом, tabular-nums. (Макет)
- Юзер-блок внизу панели: аватар (круг), имя Bold, роль — caption
  приглушённая, справа иконка настроек. (Макет)
- Каркас реализован этапом B (P1-18: фикс-сайдбар 280px, группы,
  юзер-блок); счётчики и активная плашка White — при применении §4.2.

### 4.2. Шапка списка (1fr)

- Заголовок раздела Bold; рядом табы-фильтры: активный — Ink, Medium,
  с подчёркиванием Coral; неактивные — приглушённые. (Макет)
  Состав табов задаёт информационная архитектура раздела (§8.8);
  v0.4.0 (D25 — решение владельца): табы ПО-СТАТУСНЫЕ — у заявок
  «Все / Расчёт / Согласование / В работе / Завершённые / Отменённые»,
  у лидов «Все / Новые / Рассчитанные / Выигранные / Отказ». Число
  у таба — распределение найденного по тому же поиску (API counts),
  tabular-nums. Макетные «На паузе» в домене нет.
- Поиск: поле с иконкой лупы, placeholder «Поиск по ID или клиенту…»,
  радиус полей 10px (§5). (Макет)
- Главное действие раздела — кнопка Coral (§3.1): «+ Новая заявка».

### 4.3. Карточка заявки в списке (White, 12px)

- Строка 1: номер `#LOG-7729` (tabular-nums, приглушённый) + бейдж
  статуса §3.2.
- Строка 2: заголовок маршрута Bold («Контейнер: Шанхай → Москва»);
  стрелки маршрута — обычный текст.
- Строка 3: «Клиент: …» — приглушённая подпись.
- Правый блок: ETA — Coral, Bold, tabular-nums («ETA: 24.05.2024») +
  подпись caption («Осталось 4 дня»); у завершённой — «Доставлено»
  Success; у расчётной — «Расчёт в процессе» приглушённая. (Макет)
- Степпер этапов: круги с иконками + caps-подписи (СКЛАД, ТАМОЖНЯ,
  ТРАНЗИТ, ВЫДАЧА). Завершённый этап — Success-заливка с белой
  галочкой; текущий — White с рамкой Coral и Coral-иконкой; будущий —
  приглушённый серо-тёплый. Под степпером — тонкий прогресс-бар: трек
  Sand/Border-Sand, филл Coral; завершённая заявка — филл Success;
  расчётная — короткий нейтральный. (Макет)
- Задержка — строка с круглой иконкой «!» и текстом Brick (§5.3):
  «Задержка на границе». (Макет)
- На карточке лида степпера нет — лид до конвертации этапов не имеет.
  v0.4.0 (D25): карточка лида в списке — та же анатомия без степпера
  (LeadListCard): строка 1 — дата (tabular-nums, приглушённая; лид
  номера не имеет) + бейдж статуса §3.2 (+ «Кабинет» у запросов из
  клиентского кабинета); строка 2 — маршрут Bold с типом-префиксом
  (нет маршрута — название груза); строка 3 — «Клиент: …»
  приглушённая (телефон, груз, ответственный); правый блок — цена
  выбранного варианта Coral Bold tabular-nums + caption «N вар. ·
  срок»; варианты без выбора — «Вариантов: N»; пусто — «Без расчёта»;
  у выигранного — «Заявка №N» Success; у отказа — нейтральная
  приглушённая подпись. Лента и варианты расчёта — в карточке лида.
- Карточки справочников без степпера/статуса (клиенты, договоры) —
  v0.4.0 (D25): та же сетка строк 1–3 с правым блоком-счётчиком:
  клиенты — «с {дата}», имя Bold, контакты, счётчики заявок/
  договоров/лидов; договоры — №, клиент (ссылка), юрлицо и подпись,
  счётчик заявок.

### 4.4. Детали (320px, Sand) — «Детали/Чат»

- Шапка: заголовок блока caps Coral («ДЕТАЛИ ЗАЯВКИ») + крестик
  закрытия; номер объекта Bold; caption «Последнее обновление …».
  (Макет)
- Документы: заголовок Bold «Документы (N)» + линк «+ Добавить»
  (Coral); файловая карточка — White, radius-sm: иконка типа файла
  (Coral), имя Medium, caption «Версия 2.0 · 1.2 MB», иконка
  скачивания; при выводе списка версий — таблетка V x.y (§3.2).
- История и чат: сообщение = аватар-круг + имя отправителя (Coral,
  Medium) + пузырь White radius-sm + timestamp caption; сообщение
  ИИ-ассистента — пузырь #FCEBEA и подпись «AI Assistant»; ввод снизу —
  поле «Сообщение…» + круглая кнопка отправки Coral. (Макет)
- Каркас панели уже стоит у лида («Детали/Журнал», этап B); для заявки
  — P1-19; состав «Документы + Чат» — по этому пункту.

Пропорции: 280px | 1fr | 320px.
Адаптив: при ширине < 1280px третья колонка складывается, сайдбар
скрывается на < md — зафиксировано этапом B (P1-18, замер 1440/375).

## 5. Логика ИИ-агента (System Instructions for Generation)

При генерации новых форм и карточек:

1. Скругления: 12px для карточек и 8px для кнопок.
2. Фон всех форм — `#FFFFFF` (White) для контраста с Ivory.
3. Ошибки и критичные задержки подсвечивать `#D95D39` (Brick).
4. Все кнопки «Подтвердить/Создать» — `#F28C8C` (Coral).
5. Для вторичных действий — прозрачный фон и рамка `#E5DCC5`.

Примечание: в исходнике п. 3 читался как «все отступы/критичные
задержки» — по смыслу палитры (Brick = Alerts) зафиксировано как
«ошибки и критичные задержки»; подтверждение владельца — §8.

## 6. Отображение на код

- `globals.css`: `--radius: 0.75rem` (12px); переменные `--ivory`,
  `--sand`, `--coral`, `--brick`, `--ink`, `--success`, `--border-sand`;
  маппинг shadcn: `--background`→Ivory, `--card`/`--popover`→White,
  `--primary`→Coral, `--destructive`→Brick, `--border`→Border-Sand,
  `--foreground`→Ink, сайдбар→Sand.
- `layout.tsx`: IBM Plex Sans через `next/font/google` → `--font-sans`.
- `ui/button.tsx`: default→Coral, destructive→Brick,
  outline/secondary→рамка `#E5DCC5`; вариант dark (Ink/белый) — только
  публичный сайт (§9).
- `ui/badge.tsx`: статусные варианты из §3.2 (ЗАВЕРШЕНО — визуально как
  delivered; ОЖИДАНИЕ — новый вариант pending).
- Степпер этапов и прогресс-бар (§4.3): семантические токены success /
  coral / muted — новых hex не требуется.
- Числа в таблицах и суммах: `tabular-nums` + Medium 500.
- Кнопки 8px при `--radius: 12px` — через производные токены
  (`--radius-sm/md`); финальная развязка — в этапе A (§7).
- Ограничения RULES 2.14 сохраняются: только `src/components/ui`,
  новые hex — только в `globals.css`, файл ≤ 300 строк.

## 7. Порядок применения (отдельные UI-релизы)

Репаинт не смешивается с функциональными релизами: очередь Фазы 1
(P1-04 «Деньги») не сдвигается.

- **Этап A «Токены и шрифт»:** палитра, шрифт, радиусы (`globals.css` +
  `layout.tsx` + `ui/*`) — repaint без перестройки структуры; e2e не
  затрагивается (тексты и локаторы те же).
- **Этап B «Трёхколоночный workspace»:** фиксированная навигация 280px,
  списки 1fr, правая панель 320px; складывание третьей колонки на узких
  экранах.
- **Этап C «Статусы и теги»:** бейджи по §3.2 во всех списках (включая
  ЗАВЕРШЕНО и ОЖИДАНИЕ из v1.2); печатные формы — чёрный/брендовые
  токены (print.css).
- **Референс-макеты (v1.2, D24):** анатомия списка и карточки (§4.2–4.3),
  состав панели деталей (§4.4) и лендинг (§9) применяются отдельными
  задачами после этапа C; очередь утверждает владелец (кандидаты:
  «список заявок по макету §4.2–4.3», «лендинг» — P4-01).

## 9. Публичный сайт (лендинг) — референс-макет v1.2

Источник — макет владельца «Логистика, которая думает за вас»
(24.10.2026, D24). Палитра, шрифт и радиусы — общие (§1); от админки
публичный сайт отличается акцентами, перечисленными здесь. Применение —
задача публичного фронтенда (P4-01, D17/D18); админку не затрагивает.

1. **Шапка:** лого Coral; пункты меню Ink; «Вход» — текстовая ссылка;
   «Стать клиентом» — Coral (§3.1).
2. **Hero:** таблетка-бейдж «AI-POWERED LOGISTICS» — фон `#FCEBEA`,
   текст Coral, caps; H1 Bold tracking-tight с акцент-словом Coral;
   абзац приглушённый; статистика — число Coral Bold + caps-подпись
   («15k+ грузов в год», «40+ стран»).
3. **Кнопки hero:** тёмная Ink `#2B2A26` с белым текстом — главный
   акцент публичного сайта («Рассчитать перевозку»); рядом — белая с
   рамкой Border-Sand («Смотреть демо»). Тёмная кнопка — только
   публичный сайт; в админке primary остаётся Coral (§3.1); вариант
   dark — в маппинге §6.
4. **Секции услуг/фич:** eyebrow-надзаголовок caps Coral («НАШИ
   УСЛУГИ»); White-карточки 12px; иконка Coral на плашке `#FCEBEA`
   (radius-sm); заголовки Bold; описания приглушённые.
5. **Цитата/отзыв:** карточка на Ink с белым текстом.
6. **CTA-баннер:** крупный скруглённый блок Brick с белым заголовком,
   поле email (White) + кнопка Coral; фон — открытый пункт §8.7.
7. **Футер:** светлый (Ivory/Sand), колонки ссылок с caps-заголовками,
   копирайт caption приглушённая.
8. Изображения продукта — скриншоты реальной платформы в рамках
   «окна»/устройства с радиусом карточек 12px; UI платформы заново
   не рисуется.
