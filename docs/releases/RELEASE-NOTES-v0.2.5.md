# RELEASE-NOTES v0.2.5 — редактирование лида (P1-02)

Дата: 24.10.2026 · Родитель: `f9e6e40` (v0.2.4) · Версия: 0.2.5

## Что нового для работы

1. **Анкету запроса больше не нужно пересоздавать.** В карточке лида
   (статусы «Новый» и «Рассчитан») появилась кнопка «Править анкету»:
   контакты и груз правятся в одном диалоге, бланк тот же, что при
   создании. После конвертации в заявку правка закрывается —
   дальнейшие изменения делаются в заявке.
2. **Журнал показывает, ЧТО изменилось.** Каждая правка — запись в
   ленте вида «Вес: 1 200 → 1 450; Объём: 1,8 → 2» (по полям, старое →
   новое). Менеджер видит и свои правки, и правки клиента.
3. **Клиент может сам уточнить свой запрос** — пока по нему нет ни
   одного варианта расчёта: на карточке запроса в кабинете появляется
   кнопка «Править запрос». После первого варианта правка закрывается
   (клиенту предлагается написать менеджеру). Все правки клиента видны
   в журнале лида с пометкой, что действовал клиент.
4. **Данные не теряются:** если в анкете были «нестандартные» поля
   (старые лиды, импорт), при правке они сохраняются — блок «Прочее»
   появится в P1-03.
5. Контакты в анкете правятся только у лида без клиента из
   справочника; у связанного клиента контакты живут в карточке клиента.

## Технически

- PATCH `/api/admin/leads/[id]`: `rawContact` и/или `cargoInfo`
  (окно new/calculated; won/lost — 409; без изменений — 400).
  `cargoInfo` — полная замена известных полей + сохранение неизвестных
  ключей (`lib/lead-edit.ts`: `LeadEditSchema`, `buildLeadEditDiff`,
  `mergeLeadCargo`, `isLeadAnketaEditable`).
- PATCH `/api/client/leads/[id]`: `cargoInfo`, окно «статус new + нет
  вариантов + нет заявки»; GET отдаёт `canEdit`.
- Журнал: новый тип события `lead_edited` (актёр — сотрудник или
  клиент).
- UI: новый компонент `LeadEditDialog` (админка), диалог правки в
  `ClientLeadCard` (кабинет); бланк груза — общий `CargoFormFields`.
