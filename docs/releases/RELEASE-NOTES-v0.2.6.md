# RELEASE-NOTES v0.2.6 — маршрут и груз — поля (P1-03)

Дата: 24.10.2026 · Родитель: `d6985fa` (v0.2.5) · Версия: 0.2.6

## Что нового для работы

1. **Маршрут — настоящие поля, а не текст в анкете.** Откуда/куда
   (страна и город отдельно), тип перевозки, дата готовности, вес,
   объём и места хранятся структурно — по ним работают фильтры и
   печатная форма.
2. **Фильтры списков** (лиды и заявки): строка «Откуда → Куда
   (Тип)». Приёмка роадмапа: «Китай → Москва, Море» находит заявку.
3. **Печатная форма** заполняет пункты 3 (тип), 4 (маршрут), 17
   (пункт отправления), 18 (дата), 20 (пункт прибытия) из полей.
4. **Нестандартные поля анкет не теряются** — в карточке они видны
   блоком «Прочее» (раньше был сырой JSON).
5. Журнал по-прежнему показывает diff — теперь и для маршрута:
   «Откуда: Шанхай → Китай, Шанхай», «Тип перевозки: — → Море».
6. **База: вторая миграция** — значения анкет переносятся из JSON в
   поля автоматически (откуда/куда разбираются по правилу «Страна,
   город», типы — по словарю «Авиа→air…»). Ничего не удаляется;
   перенесённые ключи убираются из JSON, остальное остаётся с
   маркером версии v: 1.

## Технически

- Схема: enum `TransportType` + 9 колонок на Lead и Order
  (Decimal(12,3)/Decimal(10,3) для веса/объёма), индексы под фильтры.
- `lib/route-fields.ts` (новый): коды/подписи типов, разбор
  «Страна, город», zod-схема route-полей; `buildLeadPayload` — единая
  сборка тел POST/PATCH из бланка (route + cargoInfo-rest).
- API: leads/orders POST/PATCH принимают `route`; конвертация В4
  переносит маршрут колонками; фильтры `?origin/destination/transport`
  в обоих списках; клиентский кабинет — тот же контракт.
- Журнал: diff route-полей общим кодом для лида и заявки; семантика
  PATCH — отсутствующее поле = «не трогать», null = очистить.
