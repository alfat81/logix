# RELEASE-NOTES v0.7.14 — Фикс «красного» CI: gitleaks на выпущенном 0.7.13 (31.10.2026)

Версия 0.7.14 (patch, RULES 2.16). База — v0.7.13. **Миграций нет, новых env нет, новых зависимостей нет. Прод-код не менялся** — деплой v0.7.13 на Vercel зелёный, продукт работает. Единственная содержательная правка — `.gitleaks.toml`. Заморозка D31 не затронута.

## Что случилось

Прогон GitHub Actions на выпущенном v0.7.13 (коммит владельца `7e3a7d0`): checks и e2e зелёные, **job gitleaks — красный, 2 находки** правила `generic-api-key`:

1. `src/lib/totp-db.test.ts:23` — `process.env.TOTP_ENCRYPTION_KEY ||= 'vitest-df09-totp-encryption-key'` (entropy 3.85).
2. `src/lib/totp-crypto.ts:38` — `enc: scryptSync(secret, 'logix-totp-enc-v1', 32)` (entropy 3.57).

Vercel-деплой того же коммита прошёл успешно — прод на v0.7.13, оба «утечения» в проде не участвуют.

## Разбор — оба срабатывания ложные, секретов нет

- **Находка 1**: одноразовый fallback-ключ интеграционного unit-теста `totp-db.test.ts`. Класс тот же, что у одноразовых значений в `ci.yml` (`ci-e2e-master-password`, `ci-e2e-totp-encryption-key`) — но те живут в env-маппинге workflow, а этот — в тест-файле, который gitleaks видит в диффе коммита. Настоящий прод-ключ `TOTP_ENCRYPTION_KEY` хранится только в env Vercel и в коде не хранится (RULES 2.4). Секретом значение не является по построению: оно защищает только тестовые шифротексты в тестовой БД.
- **Находка 2**: статическая соль scrypt и доменная развязка пары ключей (enc — шифрование секрета, mac — подпись challenge). KDF-параметры (соль) публичны по дизайну и не ослабляют криптоконтур — стойкость обеспечивается секретностью `TOTP_ENCRYPTION_KEY` (случайные 32 байта из Vercel env), а не секретностью строки-соли. Соседняя соль `'logix-totp-challenge-v1'` (строка 39) в этот прогон не попала (энтропия ниже порога правила), но добавлена в allowlist превентивно — при будущей правке соседней строки порог может её зацепить.

**Почему CI увидел находки только на релизе 0.7.13:** gitleaks в CI сканирует дифф последнего коммита (`--log-opts=-1`); релиз владельца — один squash-коммит со всем диффом DF-09, поэтому оба литерала впервые попали в скан одним куском.

## Что сделано

Сознательные границы ослабления гейта:

- **Пути файлов НЕ алловлистятся** (`src/lib/totp-crypto.ts` и тест-файл остаются под полным сканом): реальный секрет, появившийся в этих файлах, будет пойман как раньше.
- Алловлистятся только уникальные литералы не-секретов; появление другого ключа/токена в тех же файлах gitleaks по-прежнему остановит.
- Код продукта, тесты и крипто-контур DF-09 не менялись — поведение входа/профиля идентично 0.7.13.
