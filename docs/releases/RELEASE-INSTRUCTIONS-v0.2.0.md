# Инструкция владельца: деплой v0.2.0 (24.10.2026)

Время: ~10 минут. Момент выбираете сами (D14) — рекомендация «не в
рабочие часы менеджеров» в силе. Все команды — в PowerShell, в каталоге
вашего локального клона репозитория.

## 1. Распаковать архив в клон (замена поверх)

```powershell
Expand-Archive -Path .\logix-v0.2.0.zip -DestinationPath . -Force
```

Файлы из архива лягут поверх клона; ваш локальный `.env` не тронут
(его в архиве нет — намеренно).

## 2. Закоммитить и запушить

```powershell
git add -A
git commit -m "release v0.2.0: статусная модель (P1-05) и валидация дат (P1-06)"
git push origin main
```

Примечание: архив — полный снапшот. Если в вашем клоне остались файлы,
которых нет в v0.2.0 (например, старые черновики), git add -A включит
их в коммит. Перед пушем можно глянуть список: `git status`.

## 3. Дождаться зелёного CI (GitHub → Actions)

Появится новый шаг «Unit-тесты (vitest)» — это нормально. Красный CI —
не паникуем: пришлите мне лог (Actions → упавший job → Copy raw logs),
откат: `git revert HEAD --no-edit && git push`.

## 4. Дождаться деплоя Vercel

Deployments → последний коммит → Status: Ready. Новые env-переменные
этим релизом не требуются, Redeploy вручную не нужен.

## 5. Smoke на проде (~2 минуты)

1. Открыть `<ваш-адрес>/api/health` → `{"status":"ok","db":"ok"}`.
2. Войти мастером (телефон + пароль) — как обычно.
3. Открыть список заявок → карточку любой заявки → проверить, что
   страница открывается и журнал виден.
4. (Опционально) В карточке заявки перевести статус «Расчёт» →
   «Согласование» и обратно — система должна позволить. Попытка
   «Расчёт» → «Завершена» должна отклониться.

Домен может быть недоступен из России без VPN — это известное свойство
временного домена (решение D17), не признак поломки.

## 6. После деплоя — разово (не блокирует релиз)

Для будущих миграций БД по протоколу А (решение D16) поставьте себе
Node.js LTS: https://nodejs.org/ → «LTS» → установить с настройками по
умолчанию. Проверка: в новом окне PowerShell `node --version` печатает
версию (v22…). Это понадобится только когда появится релиз с миграцией.

## Если что-то пошло не так

- Откат кода: `git revert HEAD --no-edit && git push` → Vercel
  передеплоит предыдущее состояние сам.
- Схема БД не менялась — откат на уровне базы не требуется.
- Пишите мне в чат: лог CI, скриншот, что видите — разберу и дам
  следующую команду.
