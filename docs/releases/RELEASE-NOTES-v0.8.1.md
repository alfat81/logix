# RELEASE-NOTES v0.8.1 — досылка DF-11: CSP пропускает presigned PUT в S3 (03.11.2026)

Патч-релиз по находке прод-смоука DF-11. Без миграций, без новых зависимостей, схема БД не менялась.

## Что случилось на проде

Браузерная загрузка файла падала: `Refused to connect … violates Content-Security-Policy directive: "connect-src 'self'"`. CSP из E0-04 (`next.config.ts`) пускал XHR только на свой origin, а двухфазная загрузка DF-11 устроена так, что байты браузер отправляет **напрямую в хранилище** по presigned PUT — сторонний origin. В e2e дефект не проявлялся: тестовый стенд работает на локальном драйвере (same-origin `/api/storage/local`), CSP-исключение там не нужно. Скачивание и просмотр не пострадали — это top-level навигация (`target="_blank"` → 302 на presigned GET), которую `connect-src` не регулирует.

## Фикс

- В `connect-src` **при сборке** добавляется origin эндпоинта из env: `https://<host S3_ENDPOINT>` + wildcard `https://*.<host>` (страховка virtual-hosted адресации бакета). Провайдер по-прежнему задаётся env, не код (D32/D36): без `S3_*` CSP остаётся прежним «всё 'self'» — локальный драйвер same-origin.
- Минимальная гранта: `img-src`/`object-src` не расширялись — `<img>`/`iframe` на presigned-ссылки в UI нет, inline-просмотры (pdf/png/jpeg/webp) идут навигацией.
- Проверка: с `S3_ENDPOINT=https://s3.cloud.ru` → `connect-src 'self' https://s3.cloud.ru https://*.s3.cloud.ru`; без env → прежняя строка.

## Эксплуатационные уточнения (из того же смоука)

- **`S3_FORCE_PATH_STYLE=true` на проде обязателен** для Cloud.ru: virtual-hosted адрес (`<bucket>.s3.cloud.ru`) без привязанного DNS-домена бакета даёт `PUT 404`; path-style (`s3.cloud.ru/<bucket>`) равнозначен и DNS не требует (поддержка официально не прекращается). Отражено в DEPLOY.md.
- Формат ключа подтверждён продом: `S3_ACCESS_KEY_ID` = `<tenant_id>:<key_id>` (с двоеточием).
- Перенос легаси выполнен (шаг 6 D21): 2 версии, 793 884 Б, `failed:0`. Безопасность повтора скрипта подтверждена живым кейсом: упавший прогон (PUT 404) не записал `storageKey` в БД, повторный прошёл чисто.
