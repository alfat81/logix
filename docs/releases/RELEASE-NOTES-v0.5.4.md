# RELEASE-NOTES v0.5.4 — Фикс CI e2e: удаление мок-базы AI Studio (26.10.2026)

Дата: 26.10.2026. Задача: расследование красного job'а «e2e API (PostgreSQL)»
(прогоны #27–#29). Пользовательских функций нет — инфраструктурный фикс.
Версия: 0.5.4 (patch: дефект контура проверок, поведение приложения не менялось).

## Симптом

Во всех прогонах CI со времён DF-00B job «e2e API (PostgreSQL)» падал
одинаково: `admin login → 401 «Неверный телефон или пароль»`, далее каскад
«Не авторизован» и `KeyError: 'id'`. Сид при этом отчитывался о создании
мастер-учётки, health-проверка отвечала «БД доступна», статические job'ы
(checks/integrity/gitleaks) были зелёными. Локально (6 комбинаций) дефект
не воспроизводился.

## Корень

Лог приложения раннера показал ключевую строку:

```
[AI Studio] DATABASE_URL is placeholder or not set — using in-memory database mock
```

`src/lib/db.ts` (наследие шаблона AI Studio) содержал две мок-ветки:

1. `isDummyUrl()` считала «фиктивной» любую строку подключения, содержащую
   `localhost` — под это попадал и настоящий CI-раннер
   (`postgresql://logix:logix@localhost:5432/logix`). Сервер Next.js работал
   с пустым in-memory моком: сид писал мастер-учётку в реальный PostgreSQL,
   сервер искал её в моке → 401 и каскад.
2. Proxy-фолбэк на `createMockDb` при недоступности БД (P1001) — в бою
   молча подменял реальные данные.

Health-проверка «БД доступна» шла в тот же мок — поэтому E0-10 PASS
вводил в заблуждение. Обе ветки маскировали конфигурационные ошибки,
противореча принципу fail fast (З1).

## Что сделано

1. Файл `mock-db.ts` (727 строк) удалён — вместе с обеими мок-ветками.
2. `src/lib/db.ts`: единственный источник данных — PostgreSQL через
   `DATABASE_URL`; без переменной — явная ошибка при старте, никаких
   «фиктивных localhost» и тихих подмен.
3. CI, job checks: сервис `postgres:16` + `prisma migrate deploy` + сид.
   Интеграционные unit-тесты (convert-atomic, password) раньше «зеленели»
   через мок-ветку — фиктивный PASS; теперь идут по живой БД.
4. Новый `tests/setup-env.ts` (vitest `setupFiles`): загрузка `.env` для
   интеграционных unit-тестов (vitest сам `.env` не читает), только
   недостающие переменные, ничего не перезаписывает.
5. `scripts/integrity_check.py`: из IC-04 убрано исключение `mock-db.ts`
   (файла больше нет).
6. `scripts/scope_baseline_from_zip.py`: восстановление scope-baseline
   из последнего релизного архива (урок DF-00C: init после правок даёт
   пустой диф).

## Приёмка

- tsc 0 ошибок, eslint 0, vitest 39/39, build — зелёные.
- Локальный репро CI-сценария на чистой БД (миграции → сид → сервер → e2e):
  **149/149** при `CONTRACTOR_PORTAL_ENABLED=true`; сервер в логах чист

- Гейты: integrity (храповик), knip (храповик), scope (13 файлов области).

## Известное вне скоупа

(рекомендация — `node .next/standalone/server.js`). Сервер при этом
поднимается и работает; на результат e2e не влияет. Решение о смене
способа запуска — отдельной задачей (влияет на деплой владельца).
