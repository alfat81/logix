Версия 0.7.10 (patch, RULES 2.16). База — v0.7.9. 1. **Находка владельца на проде 0.7.8** (прошлый релиз, docs-only v0.7.9): «вкладки Этапы и подрядчики не приведены к общему виду» + поручение «проверь все вкладки ещё раз». Аудит нашёл 4 секции в старом стиле «голый h2 text-lg» и зафиксировал карточку DF-22 в очереди.
2. **Уточнение владельца 30.10 17:04** (скриншоты Этапы/Подрядчики/Справочники/Настройки против эталона «Юрлица»): «наполнение карточек, сравни хотя бы с юрлицами, карточки оформлены не в соответствии с брендбуком, давай внутрянку карточек приведем в соответствие» — сфера карточки расширена единой анатомией карточек.

## Что сделано

### 1. Единая анатомия карточки справочника §4.3-lite (эталон — «Юрлица», LegalEntityCard)
Строка 1 — приглушённая подпись tabular-nums («с {дата}»/номер/код) + атрибутные бейджи; строка 2 — название semibold; строка 3 — подпись muted; правый блок — счётчики/данные semibold tabular-nums + «Править» outline:
- **«Этапы»** (`StageCatalogList`): номер этапа и бейдж обязательности — строка 1, название — строка 2, код — строка 3; «Править» — outline справа; стрелки порядка на месте.
- **«Подрядчики» — «Квалификация»** (`ContractorLeadsSection`): «с {дата}» + бейдж статуса — строка 1, название — строка 2, контактное лицо и телефон — строка 3; зоны — правый блок (карточка по-прежнему открывается целиком).
- **«Подрядчики» — «Пул»** (`ContractorPoolSection`): «с {дата}» + бейдж состояния — строка 1, название — строка 2, телефон и договор — строка 3; справа — счётчик назначенных этапов (semibold tabular-nums, как счётчики юрлица) и чипы компетенций; карандаш-аффорданс сохранён.
- **«Справочники»** (`ReferencesScreen`): код — строка 1, название — строка 2, английское название — строка 3; курс ЦБ и «Править» — правый блок; шапка выровнена по эталону «Юрлица» (заголовок+подпись слева, «Обновить»/«Добавить» справа).

### 2. Секции — эталонная обёртка Card (DF-21)
`CardHeader pb-3 → CardTitle text-base` с иконкой, действие — `CardAction` в заголовке (как «+ Подключить» у брокеров):
- «Квалификация» (иконка UserSearch, «Новый кандидат» в шапке) и «Пул» (иконка Users) на странице «Подрядчики»;
- «Этапы» на карточке заявки (`order/OrderStages.tsx`, иконка ListOrdered, «Добавить этап» в шапке секции);
- «Варианты расчёта» на карточке запроса (`QuoteOptionsSection.tsx`, иконка Layers, «Добавить вариант» в шапке; пустое состояние — строка muted в CardContent, как у секции брокеров);
- группы «Настроек» (`SettingsPanel.tsx`) — `CardTitle text-base` с иконкой SlidersHorizontal вместо голого `h2 text-lg` внутри Card.

**Критерий приёмки:** `rg '<h2 className="text-lg'` по админке — **0** (кабинет подрядчика не тронут — заморожен, D31/FROZEN.md).

### 3. Фильтры «Квалификации» и «Пула» — общий ListTabs (§4.2)
Самодельные пилюли-кнопки заменены на общий `ListTabs` (активный таб — Ink Medium с подчёркиванием Action-icon). Состав табов прежний: Квалификация — «Все» + 4 статуса воронки; Пул — «В пуле/Исключённые/Все». Counts не показываются: выборка грузится по одному статусу, числам неоткуда взяться без изменений API (семантика фильтров D25 не тронута).

### 4. Остатки до-DF-20 заливок бейджей → пары §3.2
Цвет несёт точка 8px, текст тёмный; сплошная заливка — только критичное (§3.2/§3.3):
- бейдж статуса кандидата **подключён к маппингу `CONTRACTOR_LEAD_BADGE_VARIANTS`** (Новый — review, Квалификация — transit, В пуле — delivered, Отказ — version). Маппинг объявлен в `status-badges.ts` ещё в DF-20, но компонент продолжал красить сплошными `bg-info/bg-warning/bg-success/bg-destructive` — выловлен как раз этим проходом;
- «Обязательный» на «Этапах» — нейтральная **version**-пара вместо сплошного Coral-бейджа (`variant=default`): атрибут, а не срочное (§3.3 «красный только для срочного»);
- «Отключено» и «Правила — черновик (O-12)» на «Справочниках» — **version**-пара (amber-заливка была вне палитры брендбука);
- «в пуле/исключён» в диалоге кандидата — те же delivered/version, что в пуле;
- статусы «Журнала отправок» — **delivered/critical/version** вместо сплошных заливок (Ошибка — critical: единственный сплошной красный разрешён срочному);
- «чисто» на «Требует внимания» — **delivered** (счётчик при проблемах — critical, сплошной Brick-strong как и было — сигнал §3.2).

**Критерий приёмки:** сплошные `bg-info|bg-warning` в админке — 0 (полупрозрачные тинты /10–/15 меток ленты — не сплошные, разрешены); сплошной `bg-success` — только Success-круг завершённого этапа в степпере (§4.3).
