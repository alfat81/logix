## Что сделано

1. **AUD-03 — уникальность телефона пользователя компании (глобальная).** Физический уникальный индекс `CustomerUser_phone_key` + `@unique` в схеме: вход по телефону становится детерминированным. Контакты без входа (`NULL`) не ограничены. Человекочитаемый 409 сохранён, гонка выдачи доступа закрыта backstop'ом P2002. **Обязательный шаг перед миграцией на живой базе** — предпроверка дублей (SQL в инструкции, шаг 7): есть дубли — миграцию не применять, разбор с владельцем (оставляем самый старый вход).
2. **BL-8 — смена телефона только проверяемой операцией.** Два шага: запрос одноразового кода (в БД — только sha256-хеш, TTL 15 минут, лимит 5 попыток) → подтверждение кодом (атомарный захват — паттерн AUD-04). Прямая правка телефона через PATCH доступа закрыта (400 с подсказкой). До настройки WhatsApp/SMS-шлюза код выводится менеджеру в диалоге (`manual_by_manager`, см. DEPLOY.md §4.4) — сообщите клиенту по телефону/мессенджеру; событие в журнале честно помечает ручной режим. Старый вход работает до подтверждения и после (сессии не гасятся).
3. **BL-9 — перепривязка пользователя к другой компании.** Отдельная операция для не-primary пользователей: целевая компания должна существовать и быть активной; транзакция меняет привязку и **гасит все сессии** пользователя (живые вкладки старой компании умирают немедленно, повторный вход — в новую компанию). Данные прежней компании автоматически недоступны (скоупинг по привязке), история прежней компании сохраняется полностью. В списке доступа — отдельный диалог с предупреждением «Пользователь потеряет доступ к данным {старая компания}; история сохранится».
4. **AUD-04 — TOTP-код одноразов даже при гонке.** Два параллельных входа с одним кодом больше не дают две сессии: атомарный захват временного шага (отзывается ровно у одного).
5. **AUD-05 — диспетчер уведомлений: лиз-захват и восстановление зависших.** Параллельные проходы больше не «обрабатывают» одну строку дважды (лиз `sending` с арендой 15 минут, итог — только у держателя лиза). Зависшая отправка (сбой процесса после лиза) возвращается в очередь ≤15 минут автоматически либо немедленно мастером через журнал отправок; после 4 попыток — `failed` с пометкой `stuck_sending`.
6. **AUD-08 — включение TOTP требует пароль.** Закрыта асимметрия, при которой угонщик сессии мог закрепить свой второй фактор: POST без пароля — 400, с неверным — 400 (симметрия с выключением).
7. **AUD-12 — гигиена DF-14:** диалог требований этапов ≤300 строк, INVENTORY по фактическому составу.
