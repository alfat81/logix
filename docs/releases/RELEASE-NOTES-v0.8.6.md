# RELEASE-NOTES v0.8.6 — DF-14 «Чек-листы документов по этапам» + DF-26 волна 1 «Реестр документов» (06.11.2026)

Два блока одним релизом (основание: запрос владельца 06.11.2026 на передачу пакета волны 1 — D60; гейт 1 DF-26 сдан на приёмку отчётом `DF26-WAVE1-GATE1-REPORT-v1.0.md`, приёмка и production deployment — отдельные команды §6.1). В релизе **одна миграция** `20261103120000_df_14_stage_doc_requirements` — additive (новая таблица `StageDocumentRequirement` + 4 строки-дефолта), совместима с кодом 0.8.5. Env-переменных и новых зависимостей НЕТ. Номер 0.8.6 занят этим релизом; волна 2 DF-26 (`df_26_docs_center`) → 0.9.0 после гейта 2.

## Что сделано

1. **DF-14 — чек-листы обязательных документов по этапам.** Таблица `StageDocumentRequirement` (этап каталога по коду, вид документа, кто предоставляет, блокирует ли завершение). Дефолты из D5/D35 сидируются миграцией: таможенный контур импорта и экспорта — декларация на товары и разрешительный документ, предоставляет брокер; все строки «рекомендуется» (`isBlocking=false`) — блокировки подтверждает владелец (O-5). Управление — в справочнике этапов (диалог «Требования документов», только сотрудники); изменение требований пересчитывает активные заявки этапа. Завершение этапа с недостающими блокирующими документами — 400 с перечнем; обход — мастер с комментарием в журнал (единый гард перекрытия с P1-05).
2. **DF-26 волна 1 — реестр документов вместо пакета слотов.** `DocumentsPackageSection` заменён реестром `DocumentsRegistrySection` (один компонент на три кабинета): чипы-фильтры, фазы аккордеоном со счётчиками, подсветка текущего этапа, сводка панели. Группировка по фазам — из единого источника `document-phases.ts`; существующие документы классифицируются автоматически без миграции. У клиента и брокера фаза «Внутренние» и подрядческие виды не раскрываются.
3. **Строки разрешительных требований в реестре (фаза 07):** ОЖИДАЕТСЯ / ПОЛУЧЕН / НЕ ТРЕБУЕТСЯ, срок, ПРОСРОЧЕНО красным, «предоставит»; загрузка файла закрывает требование из той же строки (единая форма с зафиксированным видом `permit_document`); чужая сделка — 404, закрытая строка — 409 до отправки файла. `PermitsSection` ушла со страниц заявок (на лидах остаётся) — 8 диалогов вместо 10.
4. **ZIP по объёму:** «Скачать все» — с подтверждением и точными счётчиками состава; «Скачать финальные» — как в 0.8.5; выборочные документы — `POST {scope, documentIds}` с молчаливым исключением внутренних/чужих id. События `document_link_issued` / `document_downloaded` в ленте (без писем). **Фикс гонки К-1:** удаление документа во время сборки архива больше не даёт 500 — архив без удалённого документа либо 400; покрытие e2e + unit.
5. **Мобильная адаптация 375:** полноэкранный реестр, sticky-вкладки, карточки фаз и требований, цели ≥44×44. Кнопки «Принять/Отклонить» — волна 2 (ожидаемое отклонение от макета 10, Р-2).
