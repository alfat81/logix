# Release Notes v0.4.0 — Лиды и прочие карточки по компоновке заявки §4.2–4.3 (P1-21, D25)

Дата: 24.10.2026. Базовый релиз: v0.3.1. **Миграций нет**, схема БД не
меняется, новых env-переменных нет.

## Что внутри

Решение владельца D25: компоновка и расположение информации карточки
заявки (P1-20, BRANDBOOK §4.2–4.3) распространяется на лиды и прочие
карточки; табы списков — по-статусные. Плюс D26: чат «менеджер —
клиент — брокер» — отдельная запланированная задача (ИИ-ассистент —
дальние планы), в панель «Детали/Журнал» чат пока не добавляется.

### 1. Заявки: табы по-статусные (§4.2, D25)
- Табы «Все / Расчёт / Согласование / В работе / Завершённые /
  Отменённые» с числами (распределение найденного, API counts).
- Группа «Активные» из шапки ушла; счётчики навигации §4.1 (таблетки
  Coral в сайдбаре) и API `?status=active` сохранены.
- Единый компонент табов `ListTabs` — эталон §4.2 в одном месте,
  используется заявками и лидами.

### 2. Лиды: шапка §4.2 + новая карточка §4.3 без степпера
- Шапка как у заявок: заголовок + коралловая кнопка «Новый лид»
  (диалог вынесен в `LeadCreateDialog`, логика 1:1), по-статусные табы
  «Все / Новые / Рассчитанные / Выигранные / Отказ» с числами, поиск
  с лупой и сбросом (`LeadsToolbar`).
- **Поиск `?q=` — новое в API**: имя/телефон клиента из справочника,
  контакты rawContact (Json), название груза cargoInfo (Json).
- **Карточка `LeadListCard`** — анатомия заявки без степпера (лид до
  конвертации этапов не имеет — зафиксировано в брендбуке §4.3):
  - строка 1 — дата «от …» (лид номера не имеет) + таблетка статуса
    §3.2 + «Кабинет» у запросов из клиентского кабинета (И1);
  - строка 2 — маршрут Bold с типом-префиксом («Море: Шанхай →
    Москва»), как у заявки; нет маршрута — название груза;
  - строка 3 — «Клиент: …» с телефоном, грузом и ответственным
    (P1-01);
  - правый блок — аналог ETA: цена выбранного варианта Coral Bold +
    «N вар. · срок»; варианты без выбора — «Вариантов: N»; пусто —
    «Без расчёта»; у выигранного — «Заявка №N» (Success); у отказа —
    «Отказ».
- Фильтры P1-01 (ответственный, «давно без движения») и P1-03
  (направление, тип перевозки) — без изменений.

### 3. Прочие карточки — та же анатомия (§4.3-lite)
- **Клиенты**: «с {дата}», имя Bold, контакты; справа — «Заявок: N» +
  «Договоры: N · Лиды: N». Диалог создания вынесен в
  `CustomerCreateDialog`.
- **Договоры**: № (tabular), клиент Bold (ссылка на карточку
  клиента), юрлицо и подпись; справа — счётчик заявок.
- Брокеры/сотрудники/юрлица — следующий шаг (P1-22): сначала резка
  монолитов до ≤ 300 строк, затем та же анатомия.

### 4. Резка монолитов (RULES 2.14)
- LeadsList 493 → 226 (+ LeadListCard 173, LeadCreateDialog 213,
  LeadsToolbar 61, LeadStatusBadge 12 — реэкспорт сохранён);
  CustomersList 328 → 219 (+ CustomerCreateDialog 138); OrdersList
  287 → 266; ListTabs 51. Все файлы ≤ 300.

### 5. API (GET /api/admin/leads) — обратно совместимо
- Ответ дополнен `counts` (распределение по статусам; считается по
  тому же поиску без фильтров таба/ответственного/направления —
  семантика заявок).
- Новый параметр `?q=` (поиск). Прежние параметры `status / assigned /
  sort / origin / destination / transport` — без изменений.

### 6. Документация
- BRANDBOOK §4.2 (по-статусные табы) и §4.3 (карточка лида, карточки
  справочников) — по D25.
- DECISIONS: D25 (компоновка/табы), D26 (чат/ИИ).
- CHANGELOG [0.4.0]; ROADMAP: P1-21 закрыта, P1-22 — кандидат.
