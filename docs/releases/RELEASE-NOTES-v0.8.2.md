## Что исправлено в DEPLOY.md

1. **§3 «Локальный запуск» — структурный ремонт.** Таблица переменных окружения была вклеена внутрь bash-код-блока (между `bun install` и `cp .env.example .env`) одной из прошлых правок env-справочника; код-блок восстановлен, таблица вынесена в подраздел «Переменные окружения».
2. **§3 хранение файлов — по факту DF-11.** Раньше раздел утверждал «файлы хранятся в базе (fileData), лимит 4 МБ» и противоречил собственному DF-11-разделу в конце файла. Теперь: S3-хранилище (Cloud.ru), двухфазная загрузка мимо тела serverless-функции, лимит — настройка `files.max_mb` (по умолчанию 25 МБ, валидатор 1..200), скачивание 302 на presigned GET 60 с, легаси в `fileData` переносится `scripts/migrate-files-to-storage.ts`, HTML/SVG исключены.
3. **DF-11-раздел: правило «S3_* добавлены/изменены → Redeploy»** (RULES 2.3: после изменения env — redeploy; у `TOTP_ENCRYPTION_KEY` такой пункт был, у `S3_*` забыли). Описаны оба прод-симптома устаревшего env из смоука DF-11: `S3_*` не попали в **рантайм** — приложение молча работает на локальном драйвере, загрузка падает с 500 на `/api/storage/local/**`; `S3_*` не попали в **сборку** — CSP `connect-src 'self'` блокирует браузерный PUT (строится из `S3_ENDPOINT`/`S3_BUCKET` при сборке, v0.8.1). Добавлены смоук-признаки живого S3-драйвера: PUT уходит на `s3.cloud.ru`, возвращает 200, счётчик объектов в консоли Cloud.ru растёт; обращений к `/api/storage/local/**` нет (с настроенным S3 роут отвечает 404).
4. **§4.3 — честная фиксация подстраховки.** Суточного Vercel Cron диспетчера НЕ существует: секции `crons` в `vercel.json` не было никогда (сверка истории файла 03.11.2026), хотя карточка DF-03 и запись CHANGELOG 0.6.5 её описывали (историческая запись CHANGELOG не трогалась). Единственный источник вызовов — workflow `scheduler.yml`; крон при необходимости добавляется секцией `crons` отдельным релизом.
