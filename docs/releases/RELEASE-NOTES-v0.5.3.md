# RELEASE-NOTES v0.5.3 — DF-00C «Заморозка кабинета подрядчика» (26.10.2026)

Дата: 26.10.2026. Задача: DF-00C (docs/ROADMAP-DEALFLOW.md §7). Решение: D31.
Версия: 0.5.3 (пользовательских функций нет — контур безопасности; 0.6.0
зарезервирована за DF-01).

## Что внутри

Кабинет подрядчика закрыт до отдельного решения владельца (D31 от 25.10.2026):
не развивается, не удаляется, по умолчанию выключен. База подрядчиков
(квалификация, пул, договоры, назначение исполнителя на этап) и документы
подрядчика — НЕ заморожены и продолжают работать.

1. **Единая точка заморозки.** `src/proxy.ts` при `CONTRACTOR_PORTAL_ENABLED`
   !== `true` отвечает 404 на `/contractor/**`, `/api/contractor/**`,
   `/api/auth/contractor/**` до любой логики (API — JSON, страницы — пустой
   404), cookie подрядчика (`logix_contractor_session`) не обрабатывается.
   Matcher middleware расширен на страницы кабинета.
2. **Флаг.** `src/lib/flags.ts` — `contractorPortalEnabled()`: читается только
   на сервере и передаётся пропсами (не `NEXT_PUBLIC` — без пересборки и без
   утечки в клиентский бандл). Значение — строго строка `'true'`.
3. **Лендинг.** Ссылка «Вход для подрядчиков» рендерится только при включённом
   флаге (`src/app/page.tsx`). Ссылки брокера/клиента/сотрудников не тронуты.
4. **Диалоги выдачи доступа.** Страница «Подрядчики» стала серверной обёрткой
   (`ContractorsClient.tsx`), флаг прокидывается в секции и диалоги:
   - `ContractorPoolEditDialog` — поле «Новый пароль» скрыто при заморозке
     (пустая форма = «не менять», пароль не отправляется);
   - `ContractorLeadContractDialog` — поле «Стартовый пароль» скрыто, вместо
     него клиент генерирует случайный (`crypto.getRandomValues`, 16 символов):
     API рождения подрядчика и e2e не меняются, войти с паролем нельзя до
     разморозки. Описание диалога при заморозке объясняет D31.
5. **FROZEN.md.** Замороженные глобы (5): `src/app/contractor/**`,
   `src/app/api/contractor/**`, `src/app/api/auth/contractor/**`,
   `src/components/contractor/**`, `src/lib/contractor-auth.ts` (его потребители
   — только замороженные роуты). Вне файловых глобов: ветка `kind: 'contractor'`
   в login-guard и блок «contractor» в e2e фиксируются как регресс. Правки
   замороженного без метки `"unfreeze": true` в SCOPE — нарушение (scope.py).
6. **Интеграция проверок (G4 п.8).** `scripts/scope.py`: парсер читает ТОЛЬКО
   секцию «Замороженные глобы» FROZEN.md (остальные разделы упоминают живые
   пути), поддержаны точные пути файлов; локальный `.env` исключён из дерева
   (секреты — не часть области). `scripts/knip_check.py`: замороженные файлы
   исключены из находок и из сверяемых записей baseline (замороженный код может
   «ржаветь» молча). IC-02/IC-03, компиляция и e2e (с флагом) продолжают
   действовать.
7. **e2e в двух режимах.** Новый `scripts/e2e_contractor_frozen.py` — 16
   проверок: 404 кабинета (страница, корень, API — 404, а не 401!), вход
   подрядчика 404, лендинг без ссылки (брокер/клиент на месте), рождение
   подрядчика и база, назначение исполнителя на этап. Основной e2e (149/149)
   в CI идёт с `CONTRACTOR_PORTAL_ENABLED=true`; заморозка — отдельным шагом
   с перезапуском сервера (`DISABLE_RATE_LIMIT=true`, т.к. основной e2e
   намеренно провоцирует блокировку входа). Грабля задокументирована: guard
   принимает строго `'true'`, не `'1'`.
8. **CI-хардендинг** (после средового падения e2e на v0.5.2 — диагноз в
   worklog Task 42: код байт-в-байт совпадал с зелёным локальным репро,
   v0.5.1 был зелёным с тем же кодом логина): `bun-version: 1.4.4` запинован
   во всех трёх job (без пина setup-bun ставит latest — дрейф тулчейна
   невидим), версии bun/node/python печатаются в начале e2e-job.

## Поведение

- В проде после деплоя кабинет подрядчика закрыт автоматически (флаг не
  задан = заморожено). Существующие логины подрядчиков не работают (404),
  пароли в БД сохранены.
- Никаких миграций БД. Контракты API не менялись.
