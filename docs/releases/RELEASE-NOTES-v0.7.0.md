# Release Notes — v0.7.0 (30.10.2026)

**DF-19 «Расчёт таможенных платежей в рублях по условиям поставки» (D38/D39).** Менеджер выбирает условие поставки — система считает оценку таможенных платежей в рублях: правила берёт из справочника Инкотермс (утверждены брокером 30.10.2026, D44), курсы — снимок ЦБ на дату регистрации ДТ, сборы — по шкале ПП РФ № 1637 (ред. № 1638), распределение доп. расходов между кодами ТН ВЭД — по правилам ДТС-1 (перевозка — по весу НЕТТО гр. 38, прочие — по стоимости; переопределяется менеджером, D40). Вознаграждение брокера за ДТ — отдельная строка вне платежей (D42). Подпись «Оценка. Окончательные платежи определяются при декларировании» обязательна в интерфейсе и печатной форме (D41).

**Правила подтверждены брокером и тремя реальными ДТ клиента** (шаг 1 закрыт 30.10.2026, сверка `scripts/verify_df19_examples.py` 19/19; решения D40–D44):

- №1 `10132160/180526/5191269` — FCA авиа (FESTO, 4 кода): доли перевозки по нетто-весу совпали с ДТС-1 в ноль;
- №2 `10418010/230126/5008411` — FCA авто (Турция): цена по договору EUR при счёте TRY (номинал котировки ЦБ учтён), НДС 22% без пошлины — сходится до копейки;
- №3 `10702070/250326/5113751` — FOB море (Китай→DE): фрахт восстановлен обратным расчётом, пошлина 3%, база НДС «ТС+пошлина» видна в гр. 5010.

## Что внутри

- **Миграция `df_19_customs_calc`** (additive, протокол А): `CustomsCalculation` (снимок входных данных, курсов за единицу с датой и источником `cbr|manual`, запаса и версии правил `df19-2026.1` — расчёт воспроизводим, смена курса в справочнике сохранённые числа не меняет), `CustomsCalculationItem`, `CustomsFeeScale` (редакции шкалы по `validFrom`); nullable `incotermPlace` на `Lead`/`Order`.
- **Расчёт — чистые функции** `lib/customs.ts` (точность на BigInt, без float; единственное округление HALF_UP на финальной операции). НДС = (ТС + пошлина + доп. пошлина) × % — сбор в базу не входит. Сумма долей компонента ровно базе (копеечных потерь нет).
- **API** (только сотрудники): GET/POST `customs-calculations` на лидах и заявках, PUT — правка черновика (ответ брокера «возможность правок нужна», D40). Пересчёт создаёт новую версию, прежняя остаётся в истории (архив не правится). Событие `customs_calc_saved` — в той же транзакции.
- **UI**: экран «Расчёт таможенных платежей» в карточках запроса и заявки — форма показывает только нужные условию поставки поля (из meta справочника), строки по кодам с предзаполнением «Из ответа брокера» (DF-18), фрахт по умолчанию из выбранного варианта расчёта, курсы вручную (когда импорта на дату нет — например, курс из самой ДТ), история версий.
- **Печать**: приложение «Расчёт таможенных платежей (оценка)» к печатной форме заявки.
- **Настройка** `customs.fx_reserve_percent` (группа «Таможенные расчёты», дефолт 0) — оценочный запас к курсу ЦБ.
- **Справочники**: сид шкалы сборов 2026; draft-пометка флагов Инкотермс снята (D44) — после применения сидления экран справочника больше не показывает «черновик».

## Решения (docs/DECISIONS.md, 30.10.2026)

D40 — распределение по компонентам ДТС-1 (нетто-вес) + правки; D41 — курс: оценка по снимку на дату расчёта/регистрации, взаиморасчёты — дата оплаты; D42 — вознаграждение брокера вне баз; D43 — страхование по факту сверх цены; D44 — флаги Инкотермс утверждены для тестового контура.

## Известные ограничения (осознанно, не баги)

- Расчёт — оценка: финальные платежи определяются при декларировании; взаиморасчёты с клиентом — по курсу ЦБ на дату оплаты, если иное не оговорено в счёте (ответ брокера 30.10.2026).
- Акциз в формуле НДС зарезервирован (в ставках DF-18 не передаётся — когда появится реальный кейс, добавляется в форму расчёта без изменения модели).
- «ТС не определяется» (сбор по числу товаров) не реализован — в системе ТС всегда известна; ставки столбца сверяются по официальному тексту ПП при первой необходимости (REFERENCES-SOURCES).
- Операционное подтверждение правил на проде — после первого живого расчёта, сошедшегося с фактической ДТ (D44).
