# RELEASE-NOTES v0.7.2 — DF-05 «У кого мяч» (30.10.2026)

Версия 0.7.2 (patch, RULES 2.16). База — v0.7.1. Миграция `df_05_waiting` — additive, откат совместим (старый код колонки игнорирует). Новых env нет, новых зависимостей нет.

## Что сделано

Каждая заявка и запрос получила вычисляемое ожидание — «чего она ждёт и от кого» (карточка DF-05). Ожидание считается из состояния сделки, пишется в транзакции событий и показывается сотрудникам плашкой «Ждёт: …» (карточки списков, шапки заявки/запроса), клиенту — нейтральным текстом. На «Требует внимания» появилась секция «Ждут дольше N часов» (порог — настройка `waiting.attention_hours`, группа «Ожидания», по умолчанию 24 ч).

- **Миграция `df_05_waiting`** (additive): 4 nullable колонки на `Order` и `Lead` (`waitingOnKind`, `waitingOnId`, `waitingReason`, `waitingSince`), индексы `(waitingOnKind, waitingSince)`, CHECK допустимых значений kind; NULL = «ещё не пересчитано» (до backfill).
- **Правила** (`src/lib/waiting.ts`, чистый модуль): заявка — терминальные → none; проблема на любом этапе → менеджер; расчёт → менеджер; согласование → клиент; брокер без оценки платежей → брокер; ближайший этап без исполнителя → менеджер; просроченный план ближайшего этапа → менеджеру (6б); этап у перевозчика в срок → перевозчику. Запрос — нет проформы/инвойса и описания товара → клиент; брокер без оценки → брокер; вариантов нет → менеджер. Побеждает первое сработавшее правило; просрочка плана — семантика «Требует внимания» (план на сегодня — не просрочка, UTC).
- **Пересчёт** (`src/lib/waiting-db.ts`, единственная точка записи) вызывается из `emitEvent` в той же транзакции; событие лида пересчитывает и его заявку (оценка живёт на связи лида и меняет правило 5 заявки). `waitingSince` сдвигается только при смене kind/reason — «заявка без движения» (Ж5) считается честно.
- **Backfill** `scripts/backfill_waiting.ts` — идемпотентный пересчёт всех сделок; запуск по инструкции релиза (после `npx prisma@6 generate`).
- **UI**: `WaitingBadge` — нейтральный muted, без красного (брендбук v1.3 §3.3); секция «Ждут дольше N часов» на «Требует внимания»; клиенту — плашка «Ожидает вашего подтверждения» только когда мяч у клиента.
- **Заморозка D31 не задета**: кабинет подрядчика, его API и вход не менялись; `kind=contractor` — только внутренний маркер сотрудникам, клиенту не отдаётся; e2e-заморозка 16/16.

## Открытый вопрос владельцу (по карточке)

Правило «варианты есть, ни один не выбран → клиент (`awaiting_client_choice`)» **не добавлено** — карточка прямо предписывала проверить, есть ли в системе действие клиента «выбрал вариант». Проверка: выбор фиксирует менеджер (`PATCH /api/admin/options/[id]`, `isSelected`, `requireEmployee`), клиентского действия нет. Варианты решения: (а) оставить как есть — запрос с вариантами считается «без мяча» (сейчас так, e2e фиксирует); (б) добавить правило «ждёт выбора клиента» отдельной записью владельца в DECISIONS.md (клиент сообщает выбор менеджеру вне системы); (в) дать клиенту кнопку выбора в кабинете — изменение прав (карточка/решение владельца).

## Решения по реализации (не требуют записи в DECISIONS.md)

- Черновик оценки брокера считается «ответом» (запись есть — брокер работает; правило 5 отпускает). Отправка/статус на ожидание не влияют.
- Правило 5 на заявке смотрит оценки через лид (так же, как карточка заявки, DF-02/5а); у ручной заявки без лида правило не применяется (оценить не из чего).
- Активная заявка без этапов (ручная Б3 до наполнения) — фолбэк «мяча нет».
- Плашка ожидания — без красного: длительное ожидание красит только секция «Ждут дольше N часов» (иначе «красный шум», §3.3 брендбука v1.3).
