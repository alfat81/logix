# Logix — релиз v0.2.4 (24.10.2026)

**Задача:** P1-01 «Ответственный менеджер» — первая задача Фазы 1 по порядку очереди (D18).

## Что нового для работы

- У каждого лида и заявки появился **ответственный менеджер**. При создании лида или заявки ответственным автоматически становится тот, кто её создал; запрос из клиентского кабинета рождается «Без ответственного».
- **Смена ответственного** — в карточке лида или заявки (поле «Ответственный»): мастер выбирает сотрудника из списка, смена записывается в журнал события («Ответственный: X → Y»). Менеджер видит ответственного, но менять не может (справочник сотрудников — только мастеру, Ж6в).
- **Списки лидов и заявок**: появились кнопки «Мои» и «Без ответственного», колонка «Ответственный» и сортировка «Давно без движения» — ставит наверх записи, которые дольше всех не трогали.
- **Конвертация лида в заявку** переносит ответственного с лида; если у лида его не было — заявку ведёт тот, кто конвертировал.
- Существующие лиды и заявки при миграции получают ответственным своего создателя (по журналу событий); запросы из кабинета остаются «Без ответственного».

## Почему это первая миграция

Это первый релиз с изменением структуры базы данных после стартовой. Миграция добавляет две колонки (`assignedToId` у лидов и заявок, `updatedAt` у заявок) и заполняет ответственных по журналу. Она **не удаляет и не меняет** существующие данные; выполняется одной командой по протоколу А (решение D16) — для этого и ставился Node.js LTS (шаг 9 инструкции v0.2.3).

## Технические детали

- `Lead.assignedToId`, `Order.assignedToId` — nullable FK на Employee, индексы; `Order.updatedAt` — маркер движения (сортировка «давно без движения», Ж5).
- События журнала: `lead_assignee_changed`, `order_assignee_changed`. Повторная установка того же ответственного — 400 (тот же контракт, что у статуса); несуществующий или деактивированный сотрудник — 400; у конвертированного лида (won) ответственный не меняется — 409, ответственность живёт в заявке.
- Фильтры списков: `?assigned=mine|unassigned|all`; сортировка `?sort=stale` (`updatedAt` asc).
- FK — `ON DELETE SET NULL` (прецедент — подрядчик на этапе): API-удаления сотрудника нет; история назначений живёт в снимках Activity.
- UI: новый компонент `AssigneeField` (карточки лида и заявки); фильтры/колонка/сортировка в LeadsList и OrdersList (минимально необходимый UI по D18; большой рефакторинг карточек — отдельная задача P1-10).
