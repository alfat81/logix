# RELEASE-NOTES v0.6.0 — DF-01 «События как ось» (27.10.2026)

Дата: 27.10.2026. Задача: DF-01 «События как ось» (карточка —
`docs/ROADMAP-DEALFLOW.md` §7). Версия: 0.6.0 (minor, веха Фазы DF).
Миграция БД: **есть** (`20261026182707_df_01_event_audience`, additive).

## Для пользователя — ничего, и это нормально

Поведение интерфейса и контракты API не менялись: лента событий в
кабинете выглядит и наполняется как раньше, клиент и брокер по-прежнему
не видят внутреннего. Это фундаментальный релиз: журнал `Activity` из
«текстового лога для staff» превращён в **ось системы** — каждое событие
теперь знает свою аудиторию и привязку к этапу/документу. На этом строятся
следующие задачи: DF-02 (ленты участников сделки без второй миграции),
DF-03 (уведомления: получатель = аудитория события), DF-07 («Пульс»
владельца по этапам).

## Что сделано

### Схема данных (expand, без ломающих изменений)

- `Activity` + три колонки: `audience TEXT[]` (элементы из
  `staff|client|broker`), `stageId`, `documentId` — последние два без FK,
  как `actorId` (история живёт дольше справочников).
- Backfill внутри миграции: `isInternal = true` → `{staff}`;
  `isInternal = false` → `{staff,client,broker}` — текущая семантика
  видимости сохранена. (Значение `contractor` в прод-данных отсутствует —
  кабинет заморожен до появления этих событий; D31.)
- CHECK-констрейнт `activity_audience_nonempty`: у события не может быть
  пустой аудитории (событие без зрителей = рудимент). Страховка от ручных
  операций в БД; все пути записи в коде задают аудиторию явно.
- Колонка `isInternal` пока пишется согласованно (`audience == {staff}`) и
  читается как раньше. Её удаление — contract-релиз **0.6.3** после DF-03
  (запись в `docs/DEPRECATIONS.md`).

### `src/lib/events.ts` — единственная точка записи

- `emitEvent(tx, { target, actor, type, description, audience?, stageId?,
  documentId? })`. Аудитория по умолчанию — из реестра `EVENT_TYPES`
  (код → подпись, аудитория, правило уведомления для DF-03). Явная
  аудитория — только для событий внутренних документов
  (`documentEventAudience`).
- Канонизация: элементы только из `staff|client|broker`, дедуп и
  сортировка; посторонние значения (например, `'contractor'`) вырезаются
  с `console.error` в лог; пустой результат — событие не пишется.
- Ошибка записи события (например, P2003 — FK на ещё не созданный этап)
  **проглатывается**: журнал не валит бизнес-операцию.
- **28 точек записи в 22 файлах** переведены с `logActivity` на
  `emitEvent`; события перенесены **внутрь транзакций** своих операций
  (`$transaction`): откат изменения откатывает и событие — лента никогда
  не врёт о несостоявшемся действии (покрыто интеграционным тестом).
- Этапные события несут `stageId` (задел DF-07), документные —
  `documentId` (задел DF-03/DF-12).
- `logInternalNote` — вторая легитимная точка записи (внутренняя заметка —
  самодействие, решение гейта G2 №4). `logActivity` — deprecated-обёртка
  над `emitEvent`, оставленная **только** для замороженного роута
  подрядчика (`FROZEN.md`, D31 — правки запрещены).

### `src/lib/audience.ts` — единственная точка видимости

- `eventWhereFor(audience)`: `staff` → `{}` (видит всё),
  `client`/`broker` → `{ isInternal: false, audience: { has } }` — замена
  `ACTIVITY_EXTERNAL_WHERE` (символ остаётся реэкспортом до 0.6.3).
- `canSeeDocument(audience, doc)` — таблица истинности видимости
  документов, переиспользуется лентами документов.
- Все 4 читателя ленты переведены: дашборд админки, GET
  `orders/[id]`, GET `leads/[id]`, convert/helpers. Инвариант «роуты не
  копируют фильтры аудитории» теперь enforced охранным тестом.

### Охранные тесты (защита от откатывания архитектуры)

`src/lib/events-guard.test.ts` сканирует `src/**` и падает, если:
прямой `db.activity.create` появился вне `lib/activity.ts` + `lib/events.ts`;
`db.notification.create` появился где угодно (задел DF-03 — диспетчер
уведомлений добавится единственным разрешённым файлом); `logActivity(`
вызвался не из обёртки и замороженного роута; читатель `Activity` не
вызвал `eventWhereFor`.

### Реюз вместо дубля (находка гейта G3/IC-14)

Общий хвост отключения брокера (найти связь → снять → записать
detach-событие) вынесен в `src/lib/broker-links.ts`; роуты
`leads|orders/[id]/brokers/[brokerId]` стали тонкими обёртками.
e2e закрыло белое пятно — DELETE-роуты отключения брокера (+6 проверок).

## Замороженный контур (D31) — не задет

`git diff` по `src/app/api/contractor/**` пуст. Роут смены статуса
этапа подрядчика работает через deprecated-обёртку без единой правки;
его события продолжают получать расширенную аудиторию из backfill
(включая `contractor`), новые события значение `contractor` не пишут.

## Миграция

`20261026182707_df_01_event_audience` — только добавление: 3 колонки,
backfill `UPDATE` по пустой аудитории, CHECK-констрейнт. Таблица
`Activity` небольшая (журнал), блокировки минимальны. Откат совместим:
старый код колонки игнорирует, поэтому при откате кода миграцию не
трогаем. Дрейф схемы проверяется пустым выводом
`npx prisma@6 migrate diff --from-url "<direct>" --to-schema-datamodel prisma/schema.prisma`.
