# RELEASE-NOTES v0.8.3 — DF-11, досылка: ZIP не проходил фильтр MIME — браузерный псевдоним типа (03.11.2026)

Патч-релиз поверх v0.8.2. Повод — находка владельца: «zip-архив не проходит почему-то фильтр и не попадает в выдачу». Причина воспроизведена по коду и закрыта минимальной правкой в одной точке. Схема БД, env-контракт и зависимости не менялись; миграций нет.

## Причина (репродукция)

Шаг create двухфазной загрузки DF-11 (`normalizeUploadMime` в `src/lib/document-upload.ts`) уточнял заявленный браузером MIME по расширению файла **только** если тип пустой или `application/octet-stream`. Firefox/Windows и «Сжатая ZIP-папка» Windows (системная отправка «Сжать в ZIP») заявляют `.zip` как **`application/x-zip-compressed`** — типа нет в `DOC_ALLOWED_MIME`, он не пустой, значит fallback по расширению не срабатывал:

```
normalizeUploadMime('application/zip', 'документы.zip')              → 'application/zip'       (Chrome — работало)
normalizeUploadMime('application/x-zip-compressed', 'документы.zip') → null                    (Firefox — 400)
normalizeUploadMime('', 'документы.zip')                             → 'application/zip'       (пустой тип — работало)
```

Шаг create отвечал 400 «Формат "application/x-zip-compressed" не поддерживается. Разрешены: PDF, …, ZIP» — текст обещал ZIP, который сам же отклонял. Документ не создавался: ни в списке документов сделки, ни в выдаче скачивания его не было. Тем же механизмом часть Android-браузеров теряла `.jpg` (`image/jpg` вместо `image/jpeg`). Уязвимости нет: содержимое файла во всех случаях по-прежнему проверяется сигнатурой на confirm (E0-07), а Mime-фильтр create лишь маршрутизирует заявленный тип.

## Что сделано

1. **Карта псевдонимов `DOC_MIME_ALIASES`** (`src/lib/document-constants.ts`): `application/x-zip-compressed → application/zip`, `image/jpg → image/jpeg` — только псевдонимы форматов, уже входящих в белый список. Белый список **не расширялся**: HTML/SVG (XSS через inline-отдачу) и исполняемые форматы по-прежнему наружу.
2. **`normalizeUploadMime` сводит псевдоним к канону до проверки списка** (`src/lib/document-upload.ts`). В БД по-прежнему попадают только канонические MIME — confirm-сигнатура (`resolveFileMime`: PK\x03\x04 → family zip ↔ application/zip) и выдача (302 на presigned GET; zip — attachment octet-stream, не inline) не затронуты.
3. **Одна точка правки — все три диалога загрузки** (новый документ, новая версия, разрешительные DF-16): они идут через единственный `normalizeUploadMime` (вызовы в `createPendingDocument` и `createPendingVersion`).
4. **Тесты:** vitest +2 (псевдонимы сводятся к канону; 7z-алиас наружу не пробивается; сигнатура настоящего ZIP по каноническому типу; подмена pdf-типа с zip-байтами отклоняется); e2e +2 (ZIP с алиасом Firefox проходит create→PUT→confirm и хранится как `application/zip`; `image/jpg` с Android хранится как `image/jpeg`).
