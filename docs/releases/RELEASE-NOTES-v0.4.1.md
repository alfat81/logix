# Release Notes v0.4.1 — Терминология D27: «Запросы» вместо «Лидов» (P1-23)

Дата: 25.10.2026. Базовый релиз: v0.4.0 (коммит `a91652e`, в проде
подтверждён: health `version: a91652e`, GitHub 19 files changed).
**Миграций нет**, схема БД не меняется, новых env-переменных нет.

## Что внутри

Корректировка владельцем решения D27 (25.10.2026, тем же днём, что и
первичная фиксация): «уйти от терминологии „Лиды“ и подобного — слишком
узкоспециализировано». Введён **единый термин для всех кабинетов —
«Запрос / Запросы»**: клиентский кабинет называл сущность так с самого
начала, теперь и кабинет сотрудника. Слово «лид» снова запрещено в UI
(глоссарий RULES 2.6 переиздан, DECISIONS D27 дополнен).

Переименованы **только пользовательские тексты** — 29 файлов `src/` +
ярлыки e2e + документация; всего в релизе 37 изменённых файлов и 2
новых релизных дока.

### 1. Навигация и списки (BRANDBOOK §4.1–4.2)
- Сайдбар: раздел «Запросы» с таблеткой-счётчиком (Coral) — было
  «Лиды».
- Заголовок списка: «Запросы» (h1); хлебные крошки карточки:
  «Главная > Запросы > Запрос от …».
- По-статусные табы D25 «Все / Новые / Рассчитанные / Выигранные /
  Отказ» — **без правок**: род прилагательных совпадает с «запрос»
  («Новый запрос», «Рассчитанный запрос»).
- Пустые состояния: «Запросов пока нет — создайте первый», «Запросов
  в статусе «…» нет».
- Ошибки загрузки списка: «Не удалось загрузить запросы».

### 2. Диалоги и кнопки
- «Новый запрос» (кнопка Coral + заголовок диалога), «Создать запрос»,
  «Удалить запрос?», «Удалить запрос», «Отказ по запросу», описание
  диалога удаления («Запрос будет удалён… необратимо; запрос с заявкой
  удалить нельзя»).
- Карточка запроса: «Запрос от {дата}» (шапка), «история запроса
  зафиксирована», анкета/конвертация — «Клиент найдётся или родится из
  контактов запроса».

### 3. Тосты и ошибки API (тексты ответов)
- «Запрос создан» (+ «Статус: Новый»), «Запрос удалён», «Запрос
  обновлён», «Запрос не найден», «Не удалось создать/обновить/удалить
  запрос», «Статус запроса: …», «Запрос уже конвертирован в заявку…»,
  «У запроса есть клиент из справочника…» и др.
- Роуты затронуты текстово, не структурно: `/api/admin/leads` (CRUD,
  notes, documents, options, brokers), `/api/admin/options/[id]`,
  `/api/broker/leads/[id]/documents`.

### 4. Журнал, главная, поиск, карточки
- Журнал (SideActivityFeed + лента Activity): новые записи пишутся как
  «Запрос создан», «Запрос правлен», «Статус запроса» — исторические
  записи не переписываются (снимки текста момента).
- Главная: «Запросы без движения», «К запросам», «открыть список
  запросов».
- Глобальный поиск: секция «Запросы» (роут поиска).
- Карточка клиента: «Запросы: N», «Запросов от этого клиента пока
  нет», «Договоры: N · Запросы: N».
- Карточка заявки: «Конвертирована из запроса от …», «Запрос-источник»,
  комментарий бланка груза («у заявки без запроса бланк пуст»).
- Список клиентов: «Заявок: N · Договоров: N · Запросов: N».

### 5. e2e и тесты
- `scripts/e2e_api_test.py`: ярлыки проверок и тексты ожиданий — на
  «запрос» (тело прогонов не менялось, 149 проверок).
- `src/lib/status-machine.test.ts`: описание набора — «Матрица
  переходов запроса».

## Осознанно НЕ менялось
- Кодовые идентификаторы: `Lead`, `LeadListCard`, `LeadsList`,
  `LeadCreateDialog` и др.; URL-роуты `/api/admin/leads/*` (совместимость
  API, закладок и интеграций); комментарии в коде — доменное имя кода
  сохранено, дифф хирургический.
- Табы D25 и статусы «Новый / Рассчитан / Выигран / Отказ» — род
  совпадает.
- Исторические записи журнала Activity в БД.
- Клиентский кабинет — там «Запрос» был с самого начала.
