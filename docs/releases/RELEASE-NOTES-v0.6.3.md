# RELEASE-NOTES v0.6.3 — CI-фикс: фикстуры DF-02A под стражником паролей (28.10.2026)

## Что случилось

Коммит `9bb1b02` (release v0.6.2, DF-02A) — код и миграция корректны (миграция `df_02a_company_users` на прод применена успешно ещё до этого фикса), но CI упал на шаге `bun run test` job'а `checks`:

```
FAIL src/lib/password.test.ts > Password Verification (DF-00) > checks for un-prefixed passwords in database
AssertionError: expected 4 to be +0
```

Из-за `needs: checks` задания `integrity` и `e2e` не стартовали.

## Корневая причина (не продуктовый баг — дефект тестовых фикстур)

`src/lib/password.test.ts` (инвариант DF-00 со времён v0.5.1) — стражник, который сканирует **всю базу** и требует, чтобы пароли в `Employee`/`Customer`/`Contractor`/`Broker` имели префикс `scrypt:` (открытый текст в БД запрещён). Тесты vitest выполняются параллельно на одной БД — новые интеграционные тесты DF-02A создают свои фикстуры в той же базе одновременно со стражником.

`src/lib/company-users.test.ts` создавал 5 брокеров-обёрток («тара» для тестов пользователей) прямым `db.broker.create` с `password: 'x'` — открытым текстом (строки 72, 73, 300, 310, 442). В песочнице стражник успевал выполнить свой запрос до вставок — 0 находок, зелено; в CI тайминги сложились иначе — 4 из 5 строк уже существовали на момент запроса, красно. Гонка, а не логика.

Для справки: два других фикстурных пароля в том же релизе были оформлены правильно (`'scrypt:fixture-b5'` у employee в `company-users.test.ts`, `'scrypt:fixture-df02a-b4'` у брокера в `actor-name.test.ts`) — пять пропущенных — недосмотр Блока 5.

## Фикс

- `src/lib/company-users.test.ts`: 5 × `password: 'x'` → `password: 'scrypt:fixture-df02a'` (строка-заглушка с корректным префиксом; эти брокеры никогда не логинятся через старое поле — значение не проверяется `verifyPassword`). Инвариант «в БД нет открытых паролей» теперь соблюдён в любой момент прогона, при любом порядке тестов.
- `docs/DEPRECATIONS.md`: оценка версии contract-релиза в 5 записях сдвинута 0.6.3 → 0.6.4 (по правилу реестра «версия удаления ≤ текущей и живой код — красный CI»; 0.6.3 занят этим хотфиксом).
- `package.json` 0.6.2 → 0.6.3, `CHANGELOG.md`, статус-блок `ROADMAP.md`, релизные документы.

Продукт-код, схема, миграции, env — **без изменений**. Прод (Vercel) после деплоя v0.6.3 выполняет тот же рантайм-код, что и v0.6.2.
