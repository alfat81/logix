# RELEASE-NOTES v0.5.2 — DF-00B «Контур проверок G1–G4» (26.10.2026)

Дата: 26.10.2026. Задача: DF-00B (docs/ROADMAP-DEALFLOW.md §7). Решение: D30.
Версия: 0.5.2 (minor-версия не требуется — новых пользовательских функций нет;
0.6.0 зарезервирована за DF-01).

## Что внутри

Гейты качества G1–G4 (D30) превращены из требования добросовестности в артефакты
и автоматические проверки. Поведение приложения НЕ менялось: ни один роут, экран
и контракт API не затронуты (правки в `src` — только комментарии и 4 строки
терминологии D27).

1. **Инвентаризация (G1).** `scripts/inventory.py` генерирует `docs/INVENTORY.md`:
   292 экспорта `src/lib` с первой строкой комментария, компоненты по кабинетам,
   таблица 69 API-роутов (метод · путь · кабинет · guard · write · событие),
   23 модели Prisma с местами использования, 14 переменных окружения, скрипты
   package.json. Файл генерируемый; расхождение с кодом ловит IC-12 и CI.
2. **Контроль области изменений (G2).** `scripts/scope.py init` — снимок хешей
   дерева в `.scope-baseline.json` (не коммитится); `check` — каждый изменённый/
   добавленный/удалённый файл обязан попадать под глоб
   `docs/releases/SCOPE-v0.5.2.json`; правка замороженного (`docs/FROZEN.md`,
   D31) — нарушение без метки `unfreeze`.
3. **Целостность (G3).** `scripts/integrity_check.py` — IC-01…IC-14
   (docs/ROADMAP-DEALFLOW.md §4.7) с храповиком `scripts/integrity-baseline.json`:
   красным становится только НОВОЕ нарушение или рост baseline; baseline может
   только уменьшаться. Первичный baseline: 166 записей с причинами. IC-01
   проверяет и расхождение схемы с миграциями (shadow-БД через
   `scripts/shadow-db.ts`).
4. **Рудименты (G4).** `knip` (dev-зависимость, разрешена карточкой DF-00B) в
   режиме храповика через `scripts/knip_check.py` — 40 записей baseline.
   `docs/DEPRECATIONS.md` — реестр временно оставленного (формат ловит IC-12);
   `docs/FROZEN.md` создан пустым (наполняется в DF-00C).
5. **Автоматика.** CI: новое задание `integrity` (после `checks`):
   `inventory.py --check`, `integrity_check.py`, `knip_check.py` на сервисе
   PostgreSQL. `scripts/build-release.py` перед упаковкой запускает
   integrity/knip и не собирает архив при красном.
6. **Первичная чистка рудиментов** (уменьшение baseline):
   - удалён неиспользуемый `needsRehash` (plaintext-ветка паролей закрыта в DF-00);
   - снят фантомный `@prisma/adapter-pg` из `next.config.ts` (зависимости нет);
   - вычищены 15 упоминаний APEX и ссылок на LOGISTICS-TASK-QUEUE в
     комментариях `src`/`scripts`/`prisma`;
   - терминология D27 («запрос» вместо «лид») доведена до 4 пользовательских
     текстов: metadata layout, справка создания клиента, подсказка расчёта заявки;
   - удалены мёртвые зависимости `date-fns` и `@radix-ui/react-tabs`;
   - 28 релизных файлов версий ≤ 0.4.1 переехали в `docs/archive/releases/`
     (в `docs/releases/` — две последние версии, G4 п. 6);
   - env-документация дополнена: MASTER_*/ADMIN_*, TRUSTED_PROXY,
     DISABLE_RATE_LIMIT, BASE_URL, SHADOW_URL, платформенные VERCEL_*.
7. **P1-25 закрыта как поглощённая** (D30): автогварды RULES 2.14/2.15 — это
   IC-09/IC-14 integrity_check и knip (RULES 2.14/2.15 обновлены).
8. **Тесты самих проверок**: `scripts/test_integrity.py` — 23 фикс-кейса
   «нарушение ловится / чистое дерево проходит» на временных деревьях.
