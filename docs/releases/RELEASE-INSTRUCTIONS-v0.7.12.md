## Шаг 2. Миграция прод-базы (лечит инцидент 31.10)

`.env` в клоне должен смотреть на ПРОД-базу (Neon, direct-строка) — как при всех прошлых обновлениях. Проверка и применение:

```powershell
bunx prisma migrate status
```

Ожидается в списке `20261031060000_df_16_permits` со статусом pending (именно её не хватило проду — причина 500). Затем:

```powershell
bun run db:deploy
bunx prisma migrate status   # контроль
```

Ожидание: применение одной миграции `20261031060000_df_16_permits` и финальное «Database schema is up to date!». Если `db:deploy` ответил «No pending migrations» — база уже актуальна (инцидент был в другом), сообщить агенту. Ошибка — стоп, чат агенту. Редеплой кода на Vercel после этого шага не нужен — прод-код уже правильный, отстала только база.
