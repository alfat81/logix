# Инструкция владельца: деплой v0.2.3 (24.10.2026)

Время: ~10 минут. Все команды — готовые блоки для вставки в PowerShell
(D20). Выполняйте строго по порядку. Если контрольная точка показала
не то, что ожидается, — ОСТАНОВИТЕСЬ и пришлите мне вывод команды в чат,
ничего не коммитите.

**Важно:** публикуем релиз только командами git из PowerShell.
Загрузка файлов через сайт GitHub (кнопка «Add file → Upload files»)
для релизов запрещена — именно так 24.10 на GitHub ушёл неполный
коммит из 4 файлов документации без кода.

## 0. Привести клон в чистое состояние (работает из любого текущего)

Откройте PowerShell и скопируйте блок целиком:

```powershell
cd C:\PROJECTS\logix
git rebase --abort
git merge --abort
git fetch origin
git reset --hard origin/main
git clean -fd
git log --oneline -1
git status
```

Пояснения:

- `git rebase --abort` / `git merge --abort` могут ответить «No rebase
  in progress» / «No merge in progress» — это нормально, идите дальше.
- `git reset --hard origin/main` + `git clean -fd` делают клон точной
  копией GitHub: незакоммиченные файлы откатываются/удаляются. Ваш
  `.env` не пострадает — он игнорируется git (эти две команды его не
  трогают).
- **Контрольная точка 0:** `git log --oneline -1` должна показать
  `bb30bdf release v0.2.2: …`. `git status` — «working tree clean»
  (ничего не закоммичено и не добавлено). Если лог показывает другой
  коммит — пришлите мне вывод всего блока, ничего не делайте дальше.

## 1. Распаковать релизный архив в клон

```powershell
Remove-Item .\logix-v0.2.0.zip, .\logix-v0.2.1.zip, .\logix-v0.2.2.zip -ErrorAction SilentlyContinue
Expand-Archive -Path .\logix-v0.2.3.zip -DestinationPath . -Force
```

Файлы лягут поверх клона с заменой. Если команда выдала ошибку
«файл занят/используется» — закройте редакторы/просмотрщики, которые
могли открыть файлы проекта, и выполните блок ещё раз.

## 2. Контрольная точка 1: версия архива

```powershell
Select-String -Path .\package.json -Pattern '"version"'
```

**Ожидается:** `"version": "0.2.3"`.

Если показало `0.1.0`, `0.2.2` или другую версию — распаковался не тот
архив (или не в ту папку). ОСТАНОВИТЕСЬ, ничего не коммитьте, пришлите
мне вывод этой команды и вывод `Get-ChildItem .\*.zip`.

## 4. Закоммитить и запушить

Только если обе контрольные точки (шаги 2–3) совпали с ожиданием:

```powershell
git add -A
git commit -m "release v0.2.3: полный код P1-05/P1-06 (восстановление после неполного коммита bb30bdf) + контрольные точки релиза"
git push origin main
```

Пуш должен пройти без ошибок: клон синхронизирован с GitHub в шаге 0.
Если push отклонился — НЕ делайте `git pull` сами, пришлите мне текст
ошибки в чат.

## 5. Проверить состав коммита на GitHub (контрольная точка 3)

Откройте github.com → репозиторий `logix` → последний коммит. Над
списком файлов должно быть написано **«20 files changed»**, и в списке
должны быть `src/lib/status-machine.ts` и `package.json`.

Это ключевой признак, что релиз на этот раз полный: в прошлый раз
коммит содержал только 4 файла документации.

## 6. Дождаться зелёного CI (GitHub → Actions)

Теперь в CI появился новый шаг «Unit-тесты (vitest)» — он должен быть
зелёным. Красный CI — не паникуем: пришлите лог (Actions → упавший
job → Copy raw logs). Откат одной командой:

```powershell
git revert HEAD --no-edit
git push
```

## 7. Дождаться деплоя Vercel

Deployments → последний коммит → Status: Ready. Новые env-переменные
этим релизом не требуются, Redeploy вручную не нужен.

## 8. Smoke на проде (~2 минуты)

1. Открыть `<ваш-адрес>/api/health` → `{"status":"ok","db":"ok"}`.
2. Войти мастером (телефон + пароль) — как обычно.
3. Открыть список заявок → карточку любой заявки → страница и журнал
   открываются.
4. Перевести статус «Расчёт» → «Согласование» — система должна
   позволить. Попытка «Расчёт» → «Завершена» — отклониться. (Теперь
   это работает по-настоящему: статусная машина публикуется этим
   релизом.)

Домен может быть недоступен из России без VPN — известное свойство
временного домена (решение D17), не признак поломки.

## 9. После деплоя — разово (не блокирует релиз)

Для будущих миграций БД по протоколу А (решение D16) поставьте
Node.js LTS: https://nodejs.org/ → «LTS» → установить с настройками по
умолчанию. Проверка (в новом окне PowerShell):

```powershell

```

Должна напечататься версия (v22…). Понадобится только когда появится
релиз с миграцией.
