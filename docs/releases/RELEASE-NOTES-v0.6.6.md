# RELEASE NOTES v0.6.6 — DF-04 «Журнал отправок и повтор для мастера»

Дата: 28.10.2026 · База: v0.6.5 (`595f7a2`) · Оценка карточки: 1 д

## Что меняется для владельца

**Письма, которые не ушли, больше не теряются молча.** В кабинете появился раздел
«Журнал отправок» (`/admin/notifications`, только мастер): каждая строка очереди
уведомлений — кому, когда, в каком режиме и с каким результатом. Ошибки доставки
видны сразу и в «Требует внимания» — счётчик failed-писем на главной странице
мастера со ссылкой в журнал.

| Элемент | Что делает |
|---|---|
| Табы статусов | Все / Ждут / Отправлены / Ошибки / Пропущены — с числами из API (таб не сужает сам себя) |
| Фильтр получателя | Сотрудники / Клиенты / Брокеры |
| Ошибка доставки | Текст последнего сбоя транспорта и число попыток прямо в строке |
| «Показать полностью» | Тело письма в списке маскировано (RULES 2.4: телефоны и email), полный текст — по клику |
| «Повторить» | Для Ошибок и Пропущенных: письмо возвращается в очередь и уходит ближайшим проходом диспетчера (≤ 5 минут через scheduler + немедленная попытка) |

Повтор сознательно запрещён для отправленных (409) и ждущих (409) — двойная
отправка письма недопустима. Семантика повтора: сброс счётчика попыток, строка
сразу попадает в выборку диспетчера, история ошибки остаётся видна до следующего
результата.

Права: журнал и повтор — только мастер (менеджеру API отвечает 403, по прямой
ссылке — честная заглушка; пункт меню скрыт). Счётчик failed в «Требует внимания»
тоже уходит только мастеру — остальным ролям поле не отдаётся вовсе.

## Техническая суть

- **UI**: страница `/admin/(dashboard)/notifications` + `NotificationsJournal.tsx`
  (ListTabs по брендбуку §4.2, карточки строк, 375 px). Пункт меню «Журнал
  отправок» в `AdminNav` (`masterOnly`).
- **API**: `POST /api/admin/notifications/[id]/retry` (мастер, `{ write: true }`
  по P1-09; `no-event` — цель строка очереди, не сделка, след — сама строка);
  семантика в `src/lib/notifications/retry.ts`. `GET /api/admin/notifications`
  дополнен `counts` по статусам (для табов).
- **Внимание**: `GET /api/admin/attention` + `notificationsFailed` (мастер-only),
  секция `NotificationsFailedSection` в `AttentionSections.tsx`, входит в общий
  тотал экрана.
- **Маскирование**: `src/lib/notifications/mask.ts` — `maskPII` (email: локальная
  часть → `***`, телефон: середина → `*`), юнит-тесты 1-в-1.
- **Фикстура приёмки**: `scripts/e2e_seed_notification.ts` (bun+prisma) — прямой
  сид failed-строки «сломанного транспорта»: в e2e-окружении `EMAIL_PROVIDER=fake`
  транспорт не падает, создать failed через публичный API нельзя.
- **CI**: в env job `e2e` добавлены `EMAIL_PROVIDER=fake` и `APP_BASE_URL` — уроки
  двух красных пробежек 28.10 (без `CRON_SECRET` диспетчер 403 → 250/260; без
  провайдера дефолт `none` переводил письма в `skipped` → 253/260). Env e2e теперь
  1-в-1 с песочницей.
