# Инструкция владельца: деплой v0.4.0 (24.10.2026)

Время: ~10 минут. Все команды — готовые блоки для вставки в PowerShell
(D20). Выполняйте строго по порядку. Если контрольная точка показала
не то, что ожидается, — ОСТАНОВИТЕСЬ и пришлите мне вывод команды в чат,
ничего не коммитите.

**В этом релизе миграций НЕТ** — меняются только интерфейсы списков:
табы по-статусные у заявок и лидов (D25), новая карточка лида по
образцу заявки, поиск по лидам, карточки клиентов и договоров в общей
анатомии. Схема базы не трогается, новых env-переменных нет.

**Важно:** публикуем релиз только командами git из PowerShell.
Загрузка файлов через сайт GitHub (кнопка «Add file → Upload files»)
для релизов запрещена.

**Если v0.3.1 ещё не пушили** — не страшно: архив v0.4.0 кумулятивный
(содержит и v0.3.1, и v0.4.0), деплойте сразу его; на шаге 0 допустимы
ОБА варианта верхнего коммита (см. контрольную точку 0).

## 0. Привести клон в чистое состояние

Откройте PowerShell и скопируйте блок целиком:

```powershell
cd C:\PROJECTS\logix
git rebase --abort
git merge --abort
git fetch origin
git reset --hard origin/main
git clean -fd
git log --oneline -1
git status
```

Пояснения:

- «No rebase/merge in progress» в ответе — нормально, идите дальше.
- `git reset --hard origin/main` + `git clean -fd` делают клон точной
  копией GitHub. Ваш `.env` не пострадает — он игнорируется git.
- **Контрольная точка 0:** `git log --oneline -1` должна показать
  `release v0.3.1: …` (если v0.3.1 уже пушали) ИЛИ `5a4f1db release
  v0.3.0: …` (если нет). `git status` — «working tree clean». Другой
  коммит — пришлите мне вывод всего блока, ничего не делайте дальше.

## 1. Распаковать релизный архив в клон

Скачайте `logix-v0.4.0.zip` из чата в папку `C:\PROJECTS\logix`,
затем скопируйте блок целиком:

```powershell
Remove-Item .\logix-v0.3.1.zip -ErrorAction SilentlyContinue
Expand-Archive -Path .\logix-v0.4.0.zip -DestinationPath . -Force
```

Файлы лягут поверх клона с заменой. Ошибка «файл занят/используется» —
закройте редакторы, которые могли открыть файлы проекта, повторите блок.

## 4. Закоммитить и запушить

Только если контрольные точки 1–2 совпали:

```powershell
git add -A
git commit -m "release v0.4.0: P1-21 лиды и прочие карточки по компоновке заявки 4.2-4.3 - по-статусные табы (D25), новая карточка лида без степпера, поиск и counts в API лидов, карточки клиентов и договоров (без миграций)"
git push origin main
```

Пуш должен пройти без ошибок. Если отклонился — НЕ делайте `git pull`
сами, пришлите мне текст ошибки в чат.

CI должен быть зелёным, включая «Unit-тесты (vitest)» и «e2e API
(PostgreSQL)». Красный — не паникуем: пришлите лог (Actions → упавший

```powershell

```

База при откате не затрагивается — миграций в релизе нет.

## 8. Smoke на проде (~7 минут)

1. Открыть `<ваш-адрес>/api/health` → `{"status":"ok","db":"ok"}`,
   поле `version` — новый SHA (не `5a4f1db` и не SHA v0.3.1).
2. Войти мастером → **Лиды**: над списком — табы «Все / Новые /
   Рассчитанные / Выигранные / Отказ» с числами; активный таб
   подчёркнут коралловым. Справа от заголовка — коралловая кнопка
   «Новый лид» (диалог открывается, создание работает как раньше).
3. **Карточка лида:** дата «от …» + таблетка статуса (+«Кабинет» у
   запросов из кабинета), маршрут жирным с типом («Море: Шанхай →
   Москва»), строка «Клиент: …»; справа — цена выбранного варианта
   коралловым с подписью «N вар. · срок», либо «Вариантов: N», либо
   «Без расчёта»; у выигранного — «Заявка №N» зелёным.
4. **Поиск по лидам:** введите имя контакта или название груза —
   список и числа на табах обновляются; крестик сбрасывает.
5. **Заявки:** табы теперь «Все / Расчёт / Согласование / В работе /
   Завершённые / Отменённые» — фильтруют по одному статусу; карточка
   заявки, степпер и ETA — как в v0.3.1.
6. **Клиенты и Договоры:** карточки в общей компоновке — у клиента
   дата, имя, контакты и счётчики справа; у договора №, клиент,
   юрлицо и счётчик заявок справа.
7. **Сузьте окно до ~375px:** ничего не выходит за экран; сайдбар
   скрывается, табы переносятся.
8. **Данные не изменились:** суммы, варианты, журналы, документы,
   карточка лида/заявки, печатная форма — как в v0.3.1.

признак поломки.
