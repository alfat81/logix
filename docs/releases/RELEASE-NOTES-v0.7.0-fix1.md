# RELEASE-NOTES v0.7.0-fix1

Патч к релизу v0.7.0 (DF-19). Версия пакета НЕ растёт (KT1: остаётся 0.7.0) — архив только с изменёнными файлами (RULES 2.16).

## Причина

На проде расчёт таможенных платежей «не производился и не сохранялся». Воспроизведено на локальном стенде с точными данными сделки (ТН ВЭД 0102296100, 3900 USD, 198 кг нетто, 5% / 22%, курс USD на 27.10.2026):

1. **Ручной курс с запятой отвергался схемой.** Поле «Курсы вручную» показывает плейсхолдер `80,9604` (формат cbr.ru), но серверная zod-схема принимала только точку: `400 «Курс — число с до 4 знаками»`. Менеджер, вводящий курс как на сайте ЦБ, физически не мог сохранить расчёт. С точкой (`80.9604`) тот же расчёт сохраняется: ТС 315 745,56 ₽ · пошлина 15 787,28 · НДС 72 937,22 · сбор 2 462,00 (скобка 200–450 тыс. по шкале ПП 1637 — верно) · платежи 91 186,50 ₽.

2. **Подсказка у заблокированной кнопки была общей.** Без выбранного условия поставки кнопка «Сохранить расчёт» неактивна, а серая подпись «Условие поставки и полные строки кодов обязательны» не говорила, ЧЕГО именно не хватает.

3. **Сид пропускал плейсхолдеры.** При деплое v0.7.0 в боевую базу создалась лишняя мастер-учётка `+7XXXXXXXXXX` с паролем из переписки: скопированный из подсказки шаблон имел непустые значения, охранный гард З1 их пропустил. Удаляется вручную (DELETE по телефону); сид повторный не требуется — справочники и шкала сборов уже залиты.

## Изменения

- `src/lib/customs.ts` — `fxRatesManual`: запятая допускается (`80,9604`), нормализуется к точке на входе; битый ввод по-прежнему отклоняется (две запятые, буквы, 5 знаков).
- `src/components/admin/customs/CustomsCalcForm.tsx` — форма нормализует запятую при отправке (устойчивость к старому API); подсказка у неактивной кнопки конкретная: без условия поставки — «Выберите условие поставки…», без строк — «В каждой строке кода нужны код ТН ВЭД, стоимость товара и вес нетто».
- `scripts/seed.ts` — гард плейсхолдеров: телефон строго `+79001234567`-формата (буквы/X/скобки — отказ), пароли-шаблоны (`<сильный пароль>`, `надёжный_пароль`, `password`, `changeme`, `xxx…`, «заменя…») — отказ до записи в БД; подсказка отказа дополнена PowerShell-вариантом. Подстроки не проверяются: одноразовый пароль CI `ci-e2e-master-password` проходит (CI не ломается).
- `src/lib/customs.test.ts` — +2 теста схемы (запятая → точка; битый курс — отказ).
- Полный e2e-прогон патча выполнен в песочнице по протоколу ci.yml (reset → сид → сервер → 343 проверки); раннер — служебный скрипт конвейера, в релизные архивы не входит (урок v0.6.8: бэктик-пути в прозе — только на файлы, существующие на origin; прецедент формулировки без путей — fix3 из допатчей 0.6.8).
