# RELEASE-NOTES v0.8.0 — DF-11 «Хранилище файлов» (02.11.2026)

## DF-11: файлы — в S3-совместимое хранилище, лимит 25 МБ из настроек

Файлы больше не хранятся в Postgres (`DocumentVersion.fileData`): новые загрузки идут напрямую в S3-совместимое хранилище Cloud.ru (D36/O-8), байты через серверную функцию не проходят. Снимается лимит 4 МБ и нагрузка на базу Neon. Критерий приёмки карточки: **загрузка 20 МБ с индикацией прогресса; размер БД при загрузке не растёт** — выполнен (e2e).

- **Три шага загрузки** (все три кабинета, один контур Е): `POST` JSON-метаданных (права, лимит, белый список MIME) → presigned PUT 10 мин (`aws4fetch` — единственная новая зависимость, разрешена роадмапом) с прогрессом в диалоге → `POST …/confirm`: сервер читает **первые 1024 байта и размер** объекта, проверяет сигнатуру и лимит; несовпадение — объект удаляется, 400. HTML под видом PDF не проходит (E0-07 сохранён на confirm).
- **Скачивание:** права — **до** любого чтения тела; версия в хранилище → 302 на presigned GET 60 с (inline — только pdf/png/jpeg/webp; остальное — attachment octet-stream). Легаси-версии (байты в БД) скачиваются как прежде. Чужой документ — 404 до выдачи ссылки.
- **Лимит — настройка `files.max_mb`** (по умолчанию 25 МБ, меняется мастером в «Настройках» без выката, D32). pending-загрузки в списках скрыты; заброшенные (24 ч) вычищаются с объектами; удаление документа удаляет объекты.
- **Разрешительные (DF-16):** строка закрывается тем же confirm-ом документа (`permit_received` в той же транзакции) — «загрузить и закрыть» работает как раньше, но файл уже не идёт через БД.
- **Легаси:** старые файлы читаются из БД, пока не переносятся скриптом `scripts/migrate-files-to-storage.ts` (безопасный повтор; сначала `--dry` — отчёт). Dual-хранение до contract-релиза — `docs/DEPRECATIONS.md` (удаление колонки — 0.9.0).
- **Схема:** миграция `20261031200000_df_11_storage` — только новые колонки (`storageKey`, `status`, `fileData` nullable) и частичный индекс, без удалений (заморозка схемы 2.16).
- **Env:** `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID` (`<tenant_id>:<key_id>`), `S3_SECRET_ACCESS_KEY`, опц. `S3_FORCE_PATH_STYLE` (Vercel); без S3_* приложение работает на локальном драйвере (только dev/e2e). Бакет приватный; CORS — GET/PUT только с Origin прод-домена.
- **Находка конвейера:** буфер middleware (proxy) резал тела загрузок на 10 МиБ — capability-роут `/api/storage/local` (HMAC, аналог presigned URL S3) исключён из matcher; для S3-пути ограничение не действует (байты мимо функции).
