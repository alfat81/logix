# Инструкция владельца: деплой v0.2.2 (24.10.2026)

Время: ~10 минут. Все команды — готовые блоки для вставки в PowerShell
(D20). Выполняйте в каталоге клона (у вас `C:\PROJECTS\logix`), строго
по порядку. Если команда выдала ошибку, которую вы не понимаете, —
остановитесь и пришлите мне её текст в чат.

## 0. Восстановить клон после неудачного пуша 24.10

Клон сейчас в состоянии «застрявшего rebase» — это чинится тремя
командами:

```powershell
git rebase --abort
git fetch origin
git reset --hard origin/main
```

- `git rebase --abort` может ответить «No rebase in progress» — это
  нормально, идите к следующей команде.
- После `git reset --hard origin/main` клон = точная копия GitHub.
  Ваш `.env` не затрагивается (он не под контролем git).

## 1. Убрать старые архивы из папки клона

```powershell
Remove-Item .\logix-v0.2.0.zip, .\logix-v0.2.1.zip -ErrorAction SilentlyContinue
```

Старые архивы (v0.2.0, v0.2.1) публиковать не нужно — только v0.2.2.

## 2. Распаковать новый архив в клон (замена поверх)

```powershell
Expand-Archive -Path .\logix-v0.2.2.zip -DestinationPath . -Force
```

Файлы лягут поверх клона; ваш локальный `.env` не тронут (его в архиве
нет — намеренно).

## 3. Закоммитить и запушить

```powershell
git add -A
git commit -m "release v0.2.2: статусная модель (P1-05), валидация дат (P1-06), формат инструкций PowerShell (D20)"
git push origin main
```

Пуш должен пройти без ошибок: состояние v0.2.2 проверено сравнением с
GitHub и содержит всё, что уже лежит на сервере, плюс новые задачи.
Если push всё же отклонился — НЕ делайте `git pull` сами, пришлите мне
текст ошибки в чат.

## 4. Дождаться зелёного CI (GitHub → Actions)

Красный CI — не паникуем: пришлите лог (Actions → упавший job → Copy
raw logs). Откат одной командой:

```powershell
git revert HEAD --no-edit
git push
```

## 5. Дождаться деплоя Vercel

Deployments → последний коммит → Status: Ready. Новые env-переменные
этим релизом не требуются, Redeploy вручную не нужен.

## 6. Smoke на проде (~2 минуты)

1. Открыть `<ваш-адрес>/api/health` → `{"status":"ok","db":"ok"}`.
2. Войти мастером (телефон + пароль) — как обычно.
3. Открыть список заявок → карточку любой заявки → страница и журнал
   открываются.
4. (Опционально) Перевести статус «Расчёт» → «Согласование» и обратно —
   система должна позволить. Попытка «Расчёт» → «Завершена» должна
   отклониться.

Домен может быть недоступен из России без VPN — известное свойство
временного домена (решение D17), не признак поломки.

## 7. После деплоя — разово (не блокирует релиз)

Для будущих миграций БД по протоколу А (решение D16) поставьте
Node.js LTS: https://nodejs.org/ → «LTS» → установить с настройками по
умолчанию. Проверка (в новом окне PowerShell):

```powershell
node --version
```

Должна напечататься версия (v22…). Понадобится только когда появится
релиз с миграцией.

## Если что-то пошло не так

- Откат кода: блок из шага 4 → Vercel передеплоит предыдущее состояние
  сам.
- Схема БД не менялась — откат на уровне базы не требуется.
- Пишите мне в чат: лог CI, скриншот, что видите — разберу и дам
  следующую команду.
