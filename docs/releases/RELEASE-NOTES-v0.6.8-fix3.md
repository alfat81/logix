# RELEASE-NOTES v0.6.8-fix3 — хотфикс: красный CI integrity (IC-08, две висячие ссылки)

Дата: 29.10.2026. Основание: красный шаг integrity_check на релизном коммите
v0.6.8 (IC-08: новых 2). Формат: патч-архив (прецедент fix1/fix2/fix3 v0.6.7),
`version` в package.json не меняется. Код приложения не задет — docs-only.

## Симптом

Шаг CI `python3 scripts/integrity_check.py` на релизном коммите v0.6.8:

```
NEW  IC-08  docs/releases/RELEASE-INSTRUCTIONS-v0.6.8.md -> (скрипт конвейера N1)  ссылка на несуществующий файл
NEW  IC-08  docs/releases/RELEASE-INSTRUCTIONS-v0.6.8.md -> (скрипт конвейера N2)  ссылка на несуществующий файл
Итог: FAIL (2): новых 2, устаревших baseline 0
```

Остальные сработки (IC-03, IC-06, IC-08 x2, IC-09, IC-14) — устаревший
baseline, блокировать не могут.

## Причина

Примечание к списку КТ2 упоминало служебные скрипты релизного конвейера
(сборка патч-архивов, локальный gitleaks-прогон) бэктик-путями в прозе.
Скрипты сознательно не входят в релизные архивы — на origin их нет, и IC-08
честно поймал две висячие ссылки. В песочнице дефект не воспроизводился:
там оба скрипта существуют.

## Фикс

Примечание к КТ2 переформулировано без путей (смысл сохранён: скриптов
конвейера в составе нет и быть не должно). Исполнимые шаги деплоя,
миграции, импорт, смоук — не затронуты. Прод работает на релизном коммите,
откат не требуется: revert релизного коммита откатил бы Vercel-прод
из-за формулировки в docs, а follow-up коммит fix3 возвращает CI в зелёный
без манипуляций с продом.
