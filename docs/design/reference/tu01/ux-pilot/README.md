# ux-pilot — инвентарь переданного набора макетов (ревизия роадмапа 1.34)

Дата получения от владельца: **12.11.2026** (чат, вместе с поручением-передачей «Передача UX/UI-макетов UX Pilot в разработку Logix, который мы теперь называем TuLogistica»). Ревизия 1.34 (12.11.2026, команда владельца «правильный файл», повторная передача `homedark.png`): состав набора уточнён — 5 файлов / 5 самостоятельных экранов; идентификация `homedark.png` в ревизии 1.33 («байт-идентичная копия брокерского экрана») ошибочна и снята (хэши и размеры файлов различаются).

## Назначение

По поручению владельца переданный набор макетов UX Pilot — **основной визуальный ориентир для реализации фронтенда в рамках TU-01** (наравне с референсом LIGHT REBRANDING V2.0 и документом TU-01 Frontend Transformation v1.0 — задача фиксации TU-01.0 роадмапа 1.34). Файлы размещаются в `docs/design/reference/tu01/` **без изменений содержимого** (оригинальные имена, sha256 — в отчёте задачи TU-01.0); замена референса самостоятельной интерпретацией разработчика запрещена, каждое отступление — вопрос владельцу. Передача макетов **не означает автоматического принятия UX/UI-модели владельцем** — финальная приёмка выполняется владельцем отдельно (гейт TU-G2).

## Замеченные расхождения макетов с бизнес-правилами (обязательные исправления владельца)

Зафиксированы в роадмапе 1.33 (TU-01.0 и карточки экранов) как **обязательные исправления макетов** — выполняются при переносе в реализацию; сам референс не редактируется:

1. **`clientcabinet.png` — маржинальная стоимость:** блок «Информационная среда» содержит «…подтверждённая маржинальная стоимость» — из клиентского интерфейса убирается (клиент видит только актуальные результаты таможенных расчётов).
2. **`clientcabinet.png` — «в реальном времени»:** подзаголовок «Контролируйте ваши перевозки в реальном времени» заменяется формулировкой без обещания отслеживания в реальном времени (такая функциональность не подтверждена; статусы и ожидаемые даты — по фактическим данным системы).
3. **`commandcenter.png` — «В ЗАКАЗ»:** кнопка показана как прямое действие; в реализацию добавляется явный диалог подтверждения менеджера перед преобразованием согласованной заявки в заказ.
4. **Главная страница публичного сайта** — с ревизией 1.34 макет присутствует в наборе (`homedark.png`, тёмная тема; в ревизии 1.33 ошибочно считался копией брокерского экрана); требование владельца сохраняется: разрабатывается как самостоятельный полноценный экран, отдельно от страницы Design System; светлая тема главной — по Executive DS V2.0 / LIGHT REBRANDING V2.0.

Дополнительно зафиксировано при приёмке материалов:

- Маржинальные показатели на `commandcenter.png` (МАРЖА: 1.840 $, MARGIN // Октябрь) — интерфейс менеджера: допустимо, в клиентский интерфейс не переносится.
- Все данные на макетах — демонстрационные (ООО «Ромашка», ИП Соколов А.В., ООО «ПромТех», ИП Волков, суммы, события) — заменяются реальными данными существующей системы или явно маркируются DEMO / SAMPLE.
- Блок брокерского макета «Контроль точности» («клиент видит только финальный результат после вашего подтверждения») совпадает с действующим правилом проекта — противоречия нет.
- Светлая тема в наборе макетов экранов не представлена (включая главную — `homedark.png` только в тёмной теме) — реализуется по Executive DS V2.0 (значения светлой темы совпадают с LIGHT REBRANDING V2.0: Ivory `#FAF3E0`, поверхности `#FFFFFF`).
