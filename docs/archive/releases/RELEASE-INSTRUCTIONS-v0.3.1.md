# Инструкция владельца: деплой v0.3.1 (24.10.2026)

Время: ~10 минут. Все команды — готовые блоки для вставки в PowerShell
(D20). Выполняйте строго по порядку. Если контрольная точка показала
не то, что ожидается, — ОСТАНОВИТЕСЬ и пришлите мне вывод команды в чат,
ничего не коммитите.

**В этом релизе миграций НЕТ** — меняется только интерфейс списка
заявок и навигации: шапка раздела с табами и поиском, карточка заявки
со степпером этапов и ETA, счётчики в сайдбаре. Схема базы не трогается,
новых env-переменных нет.

**Важно:** публикуем релиз только командами git из PowerShell.
Загрузка файлов через сайт GitHub (кнопка «Add file → Upload files»)
для релизов запрещена.

## 0. Привести клон в чистое состояние

Откройте PowerShell и скопируйте блок целиком:

```powershell
cd C:\PROJECTS\logix
git rebase --abort
git merge --abort
git fetch origin
git reset --hard origin/main
git clean -fd
git log --oneline -1
git status
```

Пояснения:

- «No rebase/merge in progress» в ответе — нормально, идите дальше.
- `git reset --hard origin/main` + `git clean -fd` делают клон точной
  копией GitHub. Ваш `.env` не пострадает — он игнорируется git.
- **Контрольная точка 0:** `git log --oneline -1` должна показать
  `5a4f1db release v0.3.0: …`. `git status` — «working tree clean».
  Если лог показывает другой коммит — пришлите мне вывод всего блока,
  ничего не делайте дальше.

## 1. Распаковать релизный архив в клон

Скачайте `logix-v0.3.1.zip` из чата в папку `C:\PROJECTS\logix`,
затем скопируйте блок целиком:

```powershell
Remove-Item .\logix-v0.3.0.zip -ErrorAction SilentlyContinue
Expand-Archive -Path .\logix-v0.3.1.zip -DestinationPath . -Force
```

Файлы лягут поверх клона с заменой. Ошибка «файл занят/используется» —
закройте редакторы, которые могли открыть файлы проекта, повторите блок.

## 4. Закоммитить и запушить

Только если контрольные точки 1–2 совпали:

```powershell
git add -A
git commit -m "release v0.3.1: P1-20 список заявок по макету 4.2-4.3 - табы-группы и поиск, карточка со степпером этапов и ETA, счетчики навигации 4.1, резка OrdersList (без миграций)"
git push origin main
```

Пуш должен пройти без ошибок. Если отклонился — НЕ делайте `git pull`
сами, пришлите мне текст ошибки в чат.

## 6. Дождаться зелёного CI (GitHub → Actions)

CI должен быть зелёным, включая «Unit-тесты (vitest)» и «e2e API
(PostgreSQL)». Красный — не паникуем: пришлите лог (Actions → упавший
job → Copy raw logs). Откат одной командой:

```powershell
git revert HEAD --no-edit
git push
```

База при откате не затрагивается — миграций в релизе нет.

## 8. Smoke на проде (~7 минут)

1. Открыть `<ваш-адрес>/api/health` → `{"status":"ok","db":"ok"}`,
   поле `version` — новый SHA (не `5a4f1db`).
2. Войти мастером → **Заявки**: над списком — табы «Все / Активные /
   Завершённые / Отменённые» с числами; активный таб подчёркнут
   коралловым. Справа от заголовка — коралловая кнопка «Новая заявка»
   (открывает диалог создания — создание работает как раньше).
3. **Сайдбар:** у пунктов «Заявки» и «Лиды» — коралловые таблетки с
   числом активных объектов; активный пункт — светлая плашка.
4. **Карточка заявки в списке:** номер + таблетка статуса, маршрут
   («Море: Шанхай → Москва»), строка клиента; справа — ETA коралловым
   («Осталось N дней» или «Просрочка на N дней»); под карточкой —
   ряд кружков этапов с иконками и подписями («ЗАБОР», «ЭКСПОРТ», …),
   под ним тонкий прогресс-бар; строка «Сейчас: …» и просрочка —
   кирпичным цветом с иконкой «!».
5. **Табы фильтруют:** «Активные» — только расчёт/согласование/в работе;
   «Завершённые»/«Отменённые» — пусто, если таких заявок нет.
6. **Поиск** по номеру/клиенту/телефону работает, крестик сбрасывает.
7. **Сузьте окно до ~375px:** ничего не выходит за экран; кружки
   этапов прокручиваются внутри карточки.
8. **Данные не изменились:** суммы, варианты, журналы, документы,
   карточка заявки и печатная форма — как в v0.3.0.

Домен может быть недоступен из России без VPN (решение D17) — это не
признак поломки.
