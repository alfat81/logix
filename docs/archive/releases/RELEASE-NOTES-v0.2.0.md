# Logix — релиз v0.2.0 (24.10.2026)

Первая фазовая поставка по конвейеру «агент → архив → пуш владельца»
(docs/RULES.md 2.16). Архив `logix-v0.2.0.zip` — полный снапшот
проверенного состояния: Фаза 0 целиком + первые две задачи Фазы 1.

## Что нового для бизнеса (P1-05, P1-06)

**Заявку больше нельзя «сломать» статусом.** Перевод статусов лида и
заявки идёт только по разрешённым переходам: Расчёт → Согласование →
В работе → Завершена, отмена — из любого живого статуса. «Завершена»
ставится только когда закрыты все обязательные этапы; мастер может
закрыть осознанно — с комментарием, который навсегда остаётся в журнале
заявки. Возврат из «Завершена»/«Отменена»/«Отказа» — только мастеру и
только с причиной. Ручной перевод запроса в «Рассчитан» без единого
варианта расчёта больше не проходит (находка аудита №7).

**Даты этапов стали достоверными.** Фактическую дату нельзя поставить
будующим (опечатка «2030» отклоняется), плановая дата в прошлом при
правке помечается предупреждением, а «Завершить этап» без даты сам
фиксирует факт текущим моментом. Сводки по просрочке и печатные формы
больше не искажаются неверными датами.

## Технические изменения

- `src/lib/status-machine.ts` — матрица переходов (чистый модуль);
  `src/lib/status-machine.test.ts` — unit-тесты полного перебора.
- PATCH `/api/admin/orders/[id]`: матрица + правило завершения +
  поля `override`, `overrideComment`, `reason`; повтор статуса — 400.
- GET `/api/admin/orders/[id]`: поле `allowedTransitions` для UI.
- PATCH `/api/admin/leads/[id]`: матрица, порог «≥1 вариант» для
  «Рассчитан», возврат из «Отказа» — мастер.
- PATCH `/api/admin/orders/[id]/stages/[stageId]`: валидация дат,
  `warnings` в ответе.
- vitest + `vitest.config.ts`; CI: шаг `bun run test` в job `checks`.
