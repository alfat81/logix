## 2. Типографика

- **IBM Plex Sans** — весь интерфейс: 400 (текст), 500 (акцентные подписи), 600 (подзаголовки),
  700 (заголовки). Подключение — `next/font/local` из `src/fonts/` (woff2, latin+cyrillic, OFL);
  **сборка не зависит от доступности Google Fonts** (V-1/D79, проверено: build без обращений к
  fonts.googleapis.com). Fallback-стек: `ui-sans-serif, system-ui, sans-serif`.
- **IBM Plex Mono** — номера заявок, идентификаторы, финансовые данные, табличные показатели:
  400/500/600; fallback `ui-monospace, SFMono-Regular, Menlo, monospace`.
- Минимальный размер текста — 12px (IC-17 проверяет мелкие тексты; `text-[10px]/[11px]`/xxs запрещены).
- Карточки — радиус 12px (`--radius`), кнопки 8px, поля 10px (§5.1 v1.3 сохранён).

## 3. Правила темизации

1. Компоненты потребляют **только семантические токены** (`--c-*` через shadcn-переменные или
   Tailwind-цвета `surface`, `fg-secondary`, `accent-brand` и т.п.), а не сырые hex.
2. Тёмная тема включается классом `.dark` на `<html>`; все состояния описаны в globals.css —
   ветвление `dark:` в компонентах допустимо только для Layout-параметров, не для цветов.
3. Запрещено «механическое инвертирование» и высветление/затемнение hex на месте — новое
   значение добавляется токеном в globals.css.
4. Новый цвет → новый/существующий семантический токен в globals.css + пара в
   `docs/design/contrast-pairs.json` (IC-17). Расширять можно, сокращать нельзя.
5. Статусные бейджи: цвет несёт точка 8px, текст контрастный (§3.2); сплошная заливка —
   только delay и critical; полная спецификация пар — IC-17 × 2 темы.

## 4. Стартовая тема и режим System (замечание 2 владельца, 12.11.2026)

- **Режимы выбора — три:** Light (принудительно светлая), Dark (принудительно тёмная),
  **System** (тема устройства/браузера). Выбор сохраняется в cookie `logix-theme`
  (Path=/, срок 1 год, SameSite=Lax, Secure в production — V-3) и зеркалируется в localStorage.
- **Первый вход (нет сохранённого выбора) = System:** интерфейс стартует в теме настроек ОС/
  браузера (`prefers-color-scheme`). Стартовая тема интерфейса — результат режима System, она
  **не хардкодится**: Executive Dark — основная визуальная модель референса, Light —
  альтернативная; какую из них увидит конкретный пользователь в первый вход, определяет его
  система.
- Режим System слушает смену системной темы на лету; явный выбор Light/Dark фиксируется до
  следующей смены пользователем. Предпочтение переживает выход, повторный вход и вход другого
  пользователя в том же браузере (куки — область браузера, не учётной записи; ревизия 1.32).
- Переключение без мерцания: сервер рендерит `<html>` с классом темы по cookie, boot-скрипт
  до первой отрисовки страхует System (FOUC исключён, V-4); CSP — script-src 'unsafe-inline'
  (next.config.ts), внешних загрузок скрипт не делает.

## 5. Интерактивные состояния

| Состояние | Токены | Правило |
|---|---|---|
| Наведение | accent-hover / accent-tint | Списки — tint, кнопки-заливки — accent-hover |
| Нажатие | accent-pressed | Для заливок кнопок |
| Фокус | focus (+ ring) | `focus-visible` — кольцо ≥ 3:1 к фону; клавиатура обязательна |
| Недоступность | disabled / disabled-fg | WCAG-исключение, но пара читаема; курсор not-allowed |
| Ошибки | danger / destructive | Текст — danger; заливки кнопок — accent-strong с белым |

## 6. Доступность — цель WCAG 2.2 AA

- Пары «текст/фон» ≥ 4,5, крупные текст и UI-элементы ≥ 3,0; автоматическая проверка —
  `python3 scripts/contrast_check.py` (IC-17, 33 пары × 2 темы, 0 находок на текущем наборе).
- Соответствие **не заявляется** без проверки контраста и клавиатурной доступности
  (поручение §5): в волны TU-01.5–01.8 входят обходы Tab/Enter/Esc и фокус-видимость.
- Точка-в-точку визуальная проверка обеих тем — обязательный шаг приёмки (замечание 5
  владельца); rg-аудит hex — дополнительный инструмент, не замена.
