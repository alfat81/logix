# Журнал решений владельца Logix

Правило (docs/RULES.md, 2.12): каждое решение фиксируется датой, формулировкой
и влиянием на задачи. Изменение решения = новая запись; старая не правится.
Задача, противоречащая свежей записи журнала, останавливается до уточнения.

## 24.10.2026 — уточнения по правилам (ответы на 4 вопроса агента)

| ID | Решение | Влияние на роадмап |
|---|---|---|
| D16 | На машине владельца устанавливается Node.js LTS (вариант Б) | RULES 2.16, шаг 5: основной протокол миграций — А (`npx prisma migrate deploy` из клона, bookkeeping в `_prisma_migrations` ведётся автоматически); Neon SQL Editor (протокол Б с INSERT + sha256) — резервный. В инструкцию первого релиза входит разовый шаг «установить Node LTS» |
| D17 | Работаем на временном домене; он часто недоступен из России без VPN | Доступность домена из РФ — не признак сломанного релиза (проверки ведём с учётом этого факта). При публикации публичного фронтенда (P4-01) доступность из РФ — критерий выбора хостинга, пересматривается вместе с ревизией 152-ФЗ (D7). На бэкенд-работы не влияет |
| D18 | Фронтендом (ЛК клиента, сайт-визитка) займёмся отдельно — это большая работа; сейчас — бэкенд | Приоритет очереди: задачи Фазы 1 (деньги P1-04, статусы P1-05, валидация P1-06, e2e) и сервисные задачи Фазы 2 идут первыми; P2-02 (ЛК) и P4-01 (визитка) сдвигаются в конец. Новые UI-экраны — только минимально необходимые для бэкенд-задач; RULES 2.14 действует как ограничение, а не как источник задач |
| D19 | Варианты расчёта клиенту «подвешиваем» мы сами, добавляя свою комиссию: клиент видит варианты с нашей наценкой; себестоимость и маржу — нет | QuoteOption: себестоимость (внутренняя) и цена клиенту — раздельные данные; наценку добавляет менеджер; в клиентских проекциях — только цена клиенту; маржа не вычисляется и не отдаётся наружу (усиливает RULES 2.15, уточняет D3). Учесть в P1-03/P1-04 |
