## [0.2.7] — Фаза 1: деньги — валюта, НДС, себестоимость (P1-04, 24.10.2026)

### Деньги (P1-04, RULES 2.15, D19)
- `QuoteOption`: `priceEstimate Int` → **`price Decimal(14,2)` + `currency` (RUB/USD/EUR/CNY) + `vatMode` (с НДС / без НДС / НДС 0%)**; себестоимость — раздельные колонки `costEstimate Decimal(14,2)?` + `costCurrency` (D19: цена клиенту и себестоимость хранятся раздельно, маржа не вычисляется). **Третья миграция** p1_04_money: переименование + тип, дефолты RUB/без НДС — значения не теряются, backfill не нужен.
- `BrokerEstimate.customsDutyEstimate Int?` → `Decimal(14,2)?` (все деньги — Decimal; валюта RUB по природе платежа — ТК ЕАЭС). Брокер вводит дробные суммы, копейки — до 2 знаков.
- `lib/money.ts` — единственная точка форматирования/разбора денег (RULES 2.15): `formatMoney` (детерминированный вывод «1 450 ₽» / «1 450,50 $», группировка ru-RU), `formatMoneyWithVat`, `parseMoneyInput` («1 450,50» → число), `moneyAmount` (zod: >0 либо ≥0, до 2 знаков, потолок 10¹²). Арифметики денег нет нигде — источник правды Decimal в БД.
- Валидация API: цена/себестоимость/оценка — только числа до 2 знаков после запятой (1.234 → 400); очистка себестоимости — `null` в PATCH.
- Конвертация (В4): снимок заявки несёт `price + currency + vatMode` (cost в снимок не попадает — наружу себестоимость не выходит, D3).

### Изоляция (приёмка P1-04)
- **cost не покидает серверные проекции**: клиент, брокер и подрядчик не видят ни себестоимости, ни маржи — e2e-проверки на все три кабинета (плюс проверка отсутствия ключа `costEstimate` в ответах).
- Себестоимость видна только сотрудникам: на карточке варианта строкой «· себестоимость: …», при очистке исчезает.

### UI
- Секция «Варианты расчёта» вынесена из LeadCard (898 → 585 строк) в `QuoteOptionsSection` (214) + `QuoteOptionDialog` (158) + `QuoteOptionFormFields` (186) — правило ≤ 300 строк (RULES 2.14).
- Форма варианта: цена (десятичная) + валюта + НДС + себестоимость; карточка варианта — «1 200 000 ₽ · с НДС».
- Условия сделки заявки: цена/валюта/НДС в редакторе и на карточке; легаси-снимки (priceEstimate) читаются как RUB-фолбэк.
- Печатная форма п.23: цена с валютой и меткой НДС (та же, что в UI и БД — RULES 2.15).
- Форматирование денег centralized: локальные `fmtMoney`-копии удалены (LeadCard, LeadsList, orders page, print, brokers, лента вариантов).

## [0.2.4] — Фаза 1: ответственный менеджер (24.10.2026)

### Ответственный менеджер (P1-01)
- `Lead.assignedToId` и `Order.assignedToId` (nullable FK на Employee, индекс) + `Order.updatedAt` (маркер движения, как у лида — Ж5). **Первая миграция после baseline** — см. протокол А в инструкции релиза.
- При создании лида и ручной заявки ответственный — текущий сотрудник; запрос из клиентского кабинета (И1) рождается «Без ответственного». Конвертация лида (В4) переносит ответственного в заявку; у лида без ответственного заявку ведёт тот, кто конвертировал.
- Смена ответственного — PATCH лида/заявки (`assignedToId`: id сотрудника или null — снять) с записью в журнал (`lead_assignee_changed` / `order_assignee_changed`: «Ответственный: X → Y», назначение/снятие — отдельными формулировками). Повторная установка того же — 400 (контракт статуса); несуществующий/деактивированный сотрудник — 400; у won-лида ответственный не меняется (409) — лид после конвертации история, ответственность живёт в заявке.
- Списки лидов и заявок: фильтр `?assigned=mine|unassigned|all` («Мои / Без ответственного / Все»), колонка «Ответственный», сортировка `sort=stale` — «давно без движения» (`updatedAt` asc).
- Backfill в миграции: существующие лиды/заявки получают ответственным создателя (первое событие `lead_created`/`order_created` с актёром-сотрудником в Activity); кабинетные запросы и битые ссылки остаются NULL. Связь FK — `ON DELETE SET NULL` (прецедент — подрядчик на этапе): API-удаления сотрудника нет, история назначений живёт в Activity-снимках.

### UI (минимально необходимое по D18)
- Новый компонент `AssigneeField`: в карточках лида и заявки выбор ответственного (мастер — справочник сотрудников, менеджер — read-only подпись: справочник сотрудников читает только мастер, Ж6в). Деактивированные сотрудники в выборе не участвуют.
